# Harness Mobile「Orbit」原创视觉系统

> 状态：v0.1 设计基线  
> 适用范围：Android WebView 工作台、iOS/iPadOS 工作台、Android/iOS 原生配对与连接页  
> 目标：像成熟即时通信产品一样高效、低学习成本，但保持 Harness 的 AI 工作台身份，不复制微信的页面、图标、色值、间距、动效或组件造型。

## 1. 设计主张

**关键词：清晰、连续、可控、有生命力。**

Orbit 以“智能工作在持续运转”为品牌隐喻：

- 导航稳定：高频入口始终在固定位置；
- 状态可见：连接、运行、等待审批、任务完成均有一致反馈；
- 内容优先：大面积不透明表面，避免玻璃效果降低长文本可读性；
- 层级克制：圆角只表达分组与层级，不把每一行都做成独立胶囊；
- AI 特征：蓝青渐变仅用于活跃状态、生成进度和关键主操作，不作为满屏装饰。

### 1.1 可以借鉴的交互原则

- 四个稳定一级域，单手可达；
- 列表“标题 + 摘要 + 时间/状态”的快速扫描结构；
- 会话详情采用固定标题栏、连续消息流和底部输入区；
- 二级能力收敛到面板或设置列表，避免首页堆按钮；
- 所有重要动作都有明确状态与可恢复路径。

### 1.2 禁止照抄的边界

- 不复制微信绿、微信气泡比例、底栏图标、头像布局或“小程序/发现”命名；
- 不复制参考图中的头像、插画、装饰渐变、卡片尺寸与具体图标；
- 不把“空间、任务、模型、审批、记忆”等 Harness 能力伪装成社交功能；
- 不以相似度作为验收标准，以任务完成效率、可读性、可访问性和跨端一致性验收。

#### 渐变规则

`linear-gradient(135deg, #4968E8 0%, #4F7CEB 52%, #20BFA3 100%)`

仅可用于：

- 新建/发送等关键主操作的图标底；
- 运行中的 AI 状态环；
- 品牌空状态的小面积图形。

不得用于：页面整块背景、普通列表卡片、长文本容器。

### 2.2 字体与排版

优先系统字体，中文不捆绑字体文件：Android 使用系统 Sans，iOS 使用 SF Pro/PingFang，Web 使用 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。

| 层级 | 手机尺寸/行高 | 字重 | 场景 |
|---|---|---|---|
| Display | 28/36 | 700 | 极少量首屏引导 |
| Page title | 22/30 | 700 | 页面主标题 |
| Section title | 18/26 | 650 | 分区标题、面板标题 |
| Item title | 16/23 | 600 | 会话、文件、任务标题 |
| Body | 15/23 | 400 | 消息与说明 |
| Label | 14/20 | 600 | 按钮、标签、底栏 |
| Caption | 12/18 | 400 | 时间、状态、辅助信息 |

规则：

- 系统字体缩放 100%–200% 时不截断关键动作；
- 标题最多两行，列表摘要最多两行；
- 时间与状态不得仅依赖颜色表达；
- 中文正文不低于 15sp/15pt，交互标签不低于 14sp/14pt。

### 2.3 间距、圆角、触控

- 间距基线：`4, 8, 12, 16, 20, 24, 32`；
- 页面左右安全边距：紧凑手机 16，常规手机 20，平板内容最大宽度 720；
- 触控目标：最低 48×48，图标视觉尺寸 20–24；
- 圆角：输入/按钮 14，卡片 18，浮层/底部面板 24，头像 12 或圆形；
- 列表行优先用分隔线表达连续关系，避免每行独立 24px 大圆角；
- 只有高层级面板使用阴影：`0 8px 24px rgba(23,33,51,.10)`；深色以描边替代重阴影。

### 2.4 动效

- 即时反馈 120ms，页面/面板 220ms，状态切换 280ms；
- 曲线：`cubic-bezier(.2,.8,.2,1)`；
- 发送、创建：轻微缩放 `1 → .96 → 1`，不做弹跳；
- 运行中：低频状态环或进度条，不使用持续旋转的大型装饰；
- `prefers-reduced-motion` / iOS Reduce Motion 开启时取消位移与缩放，仅保留透明度变化。

## 3. 一级导航

固定四域：**对话 / 代理团队 / 任务 / 我的**。

### 3.1 视觉结构

- 高度：内容 58 + 底部安全区；
- 背景：不透明 `surface`，顶部 1px 分隔；
- 每项：线性原创图标 + 12–13px 标签；
- 当前项：品牌蓝图标与文字，后方使用 36×28 的轻色“轨道”底，不用微信式纯色图标；
- 非当前项：`text-tertiary`；
- 未读/异常：数字徽标上限 `99+`，任务运行使用小型进度点，不能只靠红点解释。

### 3.2 行为

- 再次点击当前 Tab：回到列表顶部；
- 每个 Tab 维持独立导航栈与滚动位置；
- 键盘弹出时底栏隐藏，输入区吸附可视视口；
- 横屏/平板：四域可转换为 72px 左侧导航轨，不把手机底栏机械拉宽。

## 4. 核心组件

### 4.1 顶部栏

- 56px 内容高 + 系统安全区；
- 左侧返回/范围入口，中部标题 + 可选状态，右侧最多两个直接动作；
- 第三个及以后动作进入更多菜单；
- 会话标题可显示模型/在线状态，但状态是辅助信息，不能挤压主标题。

### 4.2 连续列表

用于会话、代理团队、任务、设置：

- 列表外层可以是 18px 分组面板；
- 行高 68–80，左右 16；
- 图标/头像 44–48；
- 主标题 16/23，摘要 14/20；
- 右侧时间 12/18，和状态分两行；
- 行间使用从文字起点开始的细分隔，减少视觉噪声；
- 未读数字徽标只呈现服务端 read receipt：进入会话后先原位变为“正在确认”状态，最新消息载入且服务器确认后再消失；失败/旧缓存保留原数字。返回列表时保持已确认状态，多端回执到达后同步更新，不用永久 CSS 数字或点击即隐藏；
- 滑动操作仅提供快捷方式，所有操作必须另有可发现入口。

### 4.3 会话消息

Harness 会话不是人与人聊天，采用“角色栏 + 内容块”，而非复制社交气泡：

- 用户消息：右对齐的 `surface-active` 内容块，最大宽度 88%；
- Agent 回复：左侧 28px 角色标识 + 无封闭气泡的正文流；
- 对话直接触发的工具调用可使用折叠结果卡；此外只允许一张严格绑定当前 `turnId + runId` 的实时工作流卡，位于助手确认回复之后、本轮总结回复之前。代理团队成员、职责、并行代理阵容和团队摘要仍不得作为卡片插入消息流；
- 实时工作流卡默认紧凑：一行阶段与 live 状态，下一行当前动作、用时和“展开”，并以三个小型计数展示同一会话任务的已完成 / 进行中 / 待处理；底部最多显示“停止 / 查看任务”两个动作。展开后显示权威清单、真实类型、持续目标和事件流，不展示成员头像墙。卡片使用 `data-live-workflow` / `data-run-id` / `data-turn-id` / `data-session-task-summary` / `data-goal-id` 供契约验证；
- 总结回复到达时卡片以 120–220ms 过渡收起为归档摘要并停止 live 动效；下一轮生成新卡。断线、停止、失败均采用文字状态且不靠本地计时伪装权威进度；
- 文件/文档：内嵌 64px 高附件卡，显示类型、名称、大小/状态；
- 流式生成：正文末尾细光标 + 顶部/底部可见停止按钮；
- 长回复按语义段落留白，不为每一段重复头像和名称；
- 代码、表格、diff 支持横向局部滚动，不造成整页横向溢出。

### 4.4 输入区

- 默认单行 52px，展开最大为视口高度 40%；
- 左侧“＋”，正文输入，右侧发送/停止；点“＋”收起键盘并展开四列大触控面板：相册、拍摄、系统语音输入、文件。语音只在面板内出现，不占据默认主位；
- 截图导入建议显示在输入框上方，6 秒无操作自动消失；只有用户通过系统选择器确认后才显示真实缩略图。附件、权限、审批状态均可撤销，不覆盖消息流；
- Composer 正上方保留单列官方排队消息条：第一行显示“排队 N 条”和队首摘要，第二行排列编辑、删除、立即发送；360px 窄屏允许动作换行但不得横向滚动。生产复用 bridge/server 权威队列及其顺序、修订和回执，不建立本地镜像队列；
- 发送按钮使用品牌渐变图标底，但形态为“轨道箭头”，不使用社交 App 的纸飞机复刻；
- IME 开启时以 `visualViewport`/原生 inset 吸附，不能靠固定像素抬升。

### 4.5 状态与审批

- 成功 `accent`、进行中 `info`、等待 `warning`、失败 `danger`；
- 状态卡同时包含图标、标题、可读说明和操作；
- 危险操作审批使用独立底部面板：风险说明 → 影响范围 → 主/次操作；
- 删除、发布、上传等动作保持现有逐次确认与安全边界，视觉重构不得弱化确认。

### 4.6 底部面板

- 顶部 24×4 拖拽条；
- 最大高度 92dvh，圆角 24；
- 标题和关闭保持固定，内容区滚动；
- 选项列表使用单选勾选与简短说明；
- 重要表单提供固定底部保存按钮；
- Android Back、iOS 下滑、遮罩点击的关闭语义一致；有未保存内容时提示。

## 5. 分页面视觉规范

### 5.1 对话

- 首屏是连续会话列表，不设置大面积个人资料卡；
- 顶部显示“对话”，右侧新建与筛选；
- 可选工作区筛选以横向 Chips 呈现；
- 置顶、运行中、失败恢复是状态，不用多种背景色区分；
- 对话首页只呈现搜索、新建和会话列表；不混入扫码、任务或团队快捷卡。空状态只提供“新建对话”主动作。

### 5.2 代理团队

- 首页使用连续团队列表，当前运行或需要处理的团队优先；不使用联系人或群聊视觉隐喻；
- 每行显示共同目标、成员数量、运行/等待/受阻状态与最后活动时间；
- 详情用成员职责、任务状态、依赖和产出分区，状态文字先于头像装饰；
- 缺少稳定团队处理器时禁用入口并说明，不渲染虚构团队、成员或空详情页。
- 列表上方使用持续可见的“当前项目 / 来源会话”范围条：项目为主标签，来源会话为可清除次标签，并显示权威 ID 短段；不得只用容易重名的标题表达范围。
- 团队行整行可点，采用“共同目标 + 状态 + 成员/任务摘要 + 最近事件 + teamId 短段”的连续列表结构；右侧箭头只提示层级，不承载独立动作。
- 团队详情顶栏提供返回，标题下保留项目/来源会话上下文；返回后恢复原筛选、排序、滚动和展开状态。内容顺序为共同目标 → 成员职责 → 依赖 → 时间线 → 产出 → 协作画布。
- 协作画布使用节点/连线呈现成员、任务与依赖，支持双指缩放、单指平移、`− / + / 适配` 控件，以及等价的结构化列表；节点选中态同时用描边、标签和焦点表达，不能只靠颜色。

### 5.3 任务

- 顶部摘要展示“运行中 / 已启用 / 有记录”，但使用紧凑横向指标而非巨型数字卡；
- 二级分段：进行中、计划、记录；
- 任务卡明确名称、触发规则、下次时间、最近结果；
- 启用开关与立即运行分离，删除放入更多菜单，避免误触；
- 运行中的任务显示可终止、日志和预计状态。
- 任务页复用“当前项目 / 来源会话”范围条，并在其下以紧凑分型条显示“来源会话任务 / Agent Team / Project Tasks”的各自数量，再展示状态与时间筛选；三类对象使用明确类型标签和稳定 ID，不靠标题合并。范围发生变化时在列表原位更新，不弹出新的伪全局页面。
- 任务列表行整行可点，至少显示目标、权威 taskId 短段、真实类型、所属团队/会话、负责人、依赖与最近事件；同名对象以 ID 和上下文区分。
- 任务详情顶栏提供返回并持续显示来源上下文；详情以任务目标和共同目标开场，随后呈现职责、依赖/阻塞、时间线、产出/验证与关联对象。团队任务可打开聚焦当前节点的同一协作画布。
- 说明性预览数据必须在可见界面标注“样例”；实际产品列表、详情、关系和状态由 bridge/server 提供。任何实现不得从显示名称猜测 project/session/team/task 身份。

### 5.4 我的

- 个人信息用于识别与偏好，不占据半屏；
- 连接状态单独置顶，包含设备、线路、延迟与重连；
- 设置复用桌面端真实分类并按移动阅读重排：通用与外观、模型路由与代理、插件与 Skills、MCP 与连接、浏览器与定时任务、记忆与数据、关于；
- 模型页先显示“当前会话默认模型”，高级路由放入二级页；
- 记忆页明确数据来源、预算与关闭影响，避免只展示技术参数。

### 5.5 配对与断线

- 未配对页保持单一主任务：扫码连接；手动地址是次级折叠项；
- 已配对但断线时保留工作台内容，以顶部状态条提供重试；
- 切换/忘记电脑是危险操作，不能与重连并列为同级主按钮；
- Android/iOS 视觉结构一致，但相机、通知、控制能力按平台真实边界说明。

## 6. 无障碍与国际化

- 正文对比度至少 4.5:1，大文本/图形至少 3:1；
- 所有状态点、图标按钮提供文本 label 与 hint；
- 200% 字号下关键页面可滚动且操作不被遮挡；
- TalkBack/VoiceOver 顺序：标题 → 状态 → 内容 → 主要动作 → 次要动作；
- 不通过左右位置表达唯一语义，兼容 RTL；
- 中文、英文标题长度差异至少按 1.6 倍预留；
- 动态内容更新使用礼貌级 live region，流式 token 不逐字朗读。

## 7. 代码映射建议

### 7.1 Web / `mobile-compat.css`

在 `:root` 的移动媒体查询中新增 `--hm-*` token，并把当前零散的：

- `--harness-mobile-nav-height`
- `--harness-mobile-appbar-height`
- `--harness-mobile-page-gutter`
- `--harness-mobile-sheet-radius`
- `--harness-mobile-opaque-base`

逐步映射到 Orbit token；旧变量保留一版兼容别名，避免一次性破坏现有测试与选择器。

优先改造顺序：

1. 页面背景、表面、文字、边界 token；
2. app bar、底部导航与输入区；
3. 会话列表和消息流；
4. 设置/模型/任务面板；
5. 深色与高对比度。

### 7.2 Android 原生

- `colors.xml`：以 Orbit 浅色 token 替换硬编码值，`values-night/colors.xml` 对齐深色；
- `dimens.xml`：统一触控高度、页面边距、卡片圆角；
- `styles.xml`：标题、正文和按钮层级保留系统字体缩放；
- 配对、扫码、控制设置页共用同一表面与状态组件。

### 7.3 iOS 原生

- 新建语义 `Color`/`ShapeStyle` 扩展映射 Orbit，而不是在 View 中散落色值；
- 遵循 Dynamic Type、Reduce Motion、系统材质与安全区；
- `NavigationStack`、alert、confirmation dialog 保持系统交互，不为了跨端一致而仿 Android。

## 8. 首批落地验收

P0 首批必须满足：

- 四域导航在 360×640 到 430×932 范围内无横向溢出；
- 会话列表 5 秒内可识别标题、摘要、时间与运行状态；
- 会话详情的标题、消息、工具卡、附件和输入区层级清晰；
- 键盘、系统安全区、横竖屏和 200% 字体不遮挡发送/返回；
- 浅色/深色均达到对比度要求；
- Android/iOS 配对与断线状态使用同一语义体系；
- 原有审批、上传、下载、附件、返回和重连行为不被视觉改造破坏；
- 自动化测试至少覆盖 token、移动壳、设置列表、IME 抬升、深色和平台权限边界。

## 9. 评审清单

每个页面提交前回答：

1. 用户当前最主要任务是否一眼可见？
2. 是否有超过两个同级主操作？
3. 状态是否同时通过文字/图标表达？
4. 是否出现为了“像某产品”而无功能依据的组件？
5. 是否在小屏、键盘、动态字体、深色和断网下验证？
6. 是否保持既有安全确认与平台能力边界？
7. 是否优先复用 token 与核心组件，而非新增特例？
