# DeepSeek Harness 移动信息架构与 UX 蓝图

> 状态：产品与交互设计基线（待实现）  
> 适用范围：Android App、iOS/iPadOS App、手机浏览器/PWA 中的 Harness Web，以及由原生 WebView/WKWebView 承载的 Harness 工作台。  
> 核心方向：做到“像成熟国民级通信工具一样顺手”，借鉴低学习成本、强上下文连续性和单手可达等原则，但不复制微信或任何竞品的页面、图标、配色、文案、动效与功能组合。

## 1. 蓝图目标

移动端不是桌面 UI 的缩小版，也不只是一个远程 WebView。它应成为用户随时可进入的 **Harness 工作入口**：

1. 一眼知道“我在哪、什么正在进行、是否需要我处理”。
2. 三步内完成继续对话、查看代理团队、处理待办、进入桌面与移动设置。
3. Android、iOS 与 Harness Web 共享同一任务模型和导航语义；平台壳只承接配对、系统权限、连接与平台专属能力。
4. 弱网、重连、前后台切换、键盘、旋转和大字号场景不丢会话、草稿、筛选与滚动位置。
5. 高风险和低频能力不与日常入口争夺注意力。

### 1.1 设计原则

- **当前任务优先**：首屏先呈现用户正在推进的工作，而不是功能目录。
- **对象稳定、入口稳定**：对话、代理团队、任务、我的四域含义固定；同一对象不在多个域重复建档。
- **渐进披露**：高频动作直接可见，筛选、批量、诊断、连接细节进入二级页或“更多”。
- **状态先于技术**：先说“需要你确认 / 正在执行 / 已完成 / 暂时离线”，再按需展开实现细节。
- **跨端连续**：三端使用相同对象 ID、路由、草稿和导航恢复规则，而不是靠 DOM 猜测当前页面。
- **平台原生**：返回、系统选择器、权限、分享、键盘和安全区遵守 iOS/Android 平台惯例。
- **能力诚实**：iOS 不展示或暗示跨 App 手机控制；Android 控制能力始终按需授权并可立即停止。

## 2. 现状审计

### 2.1 Android

现有入口和优点：

- Launcher 进入 `MainActivity`；无配对时显示原生配对页，有配对时恢复 Web 工作台。
- 扫码为主、手动地址为后备；WebView 外有连接遮罩、重连入口和下拉刷新。
- 原生层已有 Photo Picker / 系统文件选择器、网络恢复、配对资料存储、Android 手机控制设置等能力。
- `MobileUiAdapter` 注入 `mobile-compat.css` 与 `mobile-runtime.js`，将官方 Web 的桌面侧栏改造成底部栏/抽屉，并补充移动顶栏、会话点击收起、设置页和附件入口。

主要问题：

- 移动 IA 主要通过 CSS 类名片段、可见文本和 DOM 查询“修补”桌面 Web，稳定性依赖上游结构。
- 当前移动壳重点仍是“新对话 + 会话历史 + 设置”，代理团队和任务缺少稳定一级入口。
- 原生配对、连接设置、Web 设置、Android 手机控制存在多个设置心智，入口层级容易重叠。
- 连接遮罩在部分状态下阻断全部工作台，用户难以保留上下文判断是否继续等待。

### 2.2 iOS / iPadOS

现有入口和优点：

- `ContentView` 以 `NavigationStack` 在配对页和工作台间切换，连接状态用 Banner 覆盖；系统返回、确认对话框和动态色较符合平台惯例。
- `PairingView` 提供扫码、手动地址、已配对电脑、重连和忘记电脑。
- `WorkbenchView` 使用 WKWebView，保留返回手势、交互式收键盘和系统文件上传；外链交给系统浏览器。
- 明确说明 iOS/iPadOS 只能访问 Harness 工作台，不能控制其他 App。

主要问题：

- iOS 缺少与 Android 同源的完整移动适配契约，目前仅注入附件按钮和平台标识。
- 原生顶部导航与 Web 内导航的职责尚未统一，可能出现标题、设置、返回重复。
- 工作台仍以单个 Web 容器为中心，四域路径、状态恢复和深链尚无产品级约定。
- 手机与 iPad 的主从列表模式尚未成为共享 IA 的正式组成部分。

### 2.3 Harness Web 与 Desktop 手机同步入口

现有入口和优点：

- Desktop 的“手机与远程同步”已覆盖开启同步、二维码/配对地址、设备列表、远程线路、Android 控制状态和停止动作。
- Web 工作台已有会话、工作区、任务/团队、设置、文件、定时任务、浏览器等真实对象和能力。
- 已有语义属性如 `data-slot="sidebar"`、`data-slot="conversation"`、`data-composer-card`，可作为共享移动契约的起点。

主要问题：

- Desktop 手机同步弹层信息密度高，把首次配对、线路高级设置、设备管理和手机控制放在同一长页。
- 工作台对象虽然齐全，但移动端仍以桌面结构折叠，缺少面向拇指操作和中断恢复的一级架构。
- Android 与 iOS 注入方式分叉；Web 本身没有对四域、移动顶栏、底栏、抽屉、系统回退暴露稳定 API。
- “任务”既可能指会话里的 todo、Agent Team 任务、后台命令或定时任务，移动端需要统一展示层而不能混为一种数据。

### 2.4 审计结论

不应继续增加平台注入规则来模拟完整产品壳。目标架构应是：

- **原生接入层**：配对、连接、更新、系统权限、平台专属能力。
- **共享移动工作台层**：四域导航、页面层级、对象状态、草稿和深链。
- **能力详情层**：由插件/服务提供内容，但服从统一入口、状态与返回契约。

## 3. 原创四域信息架构

### 3.1 一级导航

已配对且进入工作台后，手机使用固定四域底部导航：

| 一级域 | 用户心智 | 默认首页 | 角标规则 |
| --- | --- | --- | --- |
| **对话** | 与 Harness 沟通和继续上下文 | 最近对话 / 当前对话 | 仅“需要用户处理”的未读，不用生成 token 数量做角标 |
| **代理团队** | 哪些代理正在协作、由谁负责 | 当前与最近团队 | 只标记需要人工处理的团队状态 |
| **任务** | 什么正在执行、等我处理、已经完成 | 关注队列 | 只统计需要输入、受阻、待审，不统计普通运行中 |
| **我的** | 设备、连接、偏好与安全 | 我的首页 | 只显示必须处理的权限、更新或安全问题 |

规则：

- 四域只在“已进入工作台”的主层显示；配对、扫码、阻断式更新不显示底栏。
- 底栏不是桌面侧栏的视觉搬运，而是移动端稳定路由；每项拥有独立图标语义与文字标签。
- 当前域再次点击：若已在根页，则回到列表顶部；若在二级页，则返回该域根页。
- 长按、双击或滑动不得承载唯一功能。
- 平板宽度 ≥ 700 pt/dp 时，底栏转为可折叠侧栏，但域名、顺序和路由不变。

### 3.2 对话域

```text
对话
├─ 继续当前对话（有活动上下文时置顶）
├─ 最近
│  ├─ 需要我处理
│  ├─ 进行中
│  └─ 其他最近对话
├─ 搜索
├─ 已固定
└─ 历史（按时间增量加载）
   └─ 对话详情
      ├─ 消息流（用户消息、对话回复，以及严格绑定本轮生命周期的实时工作流卡）
      ├─ 输入与附件
      ├─ 会话日志
      └─ 更多：重命名、固定、查看关联代理团队、归档
```

- “新对话”是对话首页和详情顶栏的明确主动作。
- 对话列表默认按“是否需要我处理 → 最近活动”排序，不把所有流式更新都顶到最前。
- 列表右侧未读计数只来自服务端 read receipt。用户进入会话后，必须先成功载入服务端确认的最新消息，再提交/收到该 `conversationId + latestMessageId` 的已读回执，计数才清零并消失；载入失败、离线旧缓存或仅完成页面跳转都不得抢先清零。
- 已读状态按服务端游标/修订在多端同步；任一端的新回执到达后其他端原位更新，同步冲突以服务端为准。确认期间可显示“正在确认已读”，失败时恢复原计数并提供重试，不把 CSS 隐藏当成已读。
- 对话消息流只允许一种非消息执行卡：用户消息 → 助手确认回复之后，为该 `turnId` 展开一张绑定权威 `runId` 的实时工作流卡；下一条本轮总结回复到达前，它持续展示阶段、当前动作、用时与“停止 / 查看任务”，默认紧凑且可展开权威事件流。
- 紧凑态同时显示同一会话任务的“已完成 / 进行中 / 待处理”计数；展开态显示权威清单、每项真实类型与持续目标。持续目标跨本轮可复用，但必须携带权威 `goalId` 和修订号，不能把卡片文案另存为一份本地任务或目标。
- 总结回复到达时，实时工作流卡立即停止实时订阅、自动收起为可回看的归档摘要；下一轮用户消息必须创建新的 `turnId + runId` 卡，不复用或改写上一轮。团队成员、并行代理、职责或团队摘要卡仍禁止进入消息流，完整协作只在代理团队/任务域展示。
- Composer 正上方显示官方排队消息条：明确排队数量和当前队首摘要，并提供编辑、删除、立即发送。生产端必须直接订阅并操作 bridge/server 的权威会话队列，复用其 `queueId/messageId/revision`、排序、冲突和失败语义；不得在移动端复制一份本地队列或乐观伪造删除/发送成功。
- 输入区“＋”使用原创四宫格动作面板：相册、拍摄、系统语音输入、文件；相册/文件走系统选择器，拍摄走系统相机安全 URI，语音委托系统识别并回填当前草稿，不静默申请图库或录音访问。检测到可导入截图时仅在输入框上方显示临时建议，6 秒未操作自动消失；用户确认选择后才生成真实缩略图，可移除或取消。草稿绑定 `conversationId + deviceId` 并跨域保留。

### 3.3 代理团队域

“代理团队”呈现真实 Agent Team、子代理和协作任务，不把团队伪装成联系人或群聊，也不在此重复对话内容。

```text
代理团队
├─ 当前团队（有人工作或需要处理时置顶）
├─ 最近团队
├─ 单个子代理运行摘要
└─ 团队详情
   ├─ 共同目标与状态
   ├─ 成员、职责和当前任务
   ├─ 依赖、阻塞与待人工处理
   ├─ 产出与验证证据
   └─ 更多：打开关联对话、任务或桌面端团队设置
```

- 团队列表只显示服务端返回的真实团队、成员和任务；没有稳定接口时入口必须禁用并说明，不创建占位业务页。
- 当前团队状态优先于头像装饰：运行中、等待输入、受阻、已完成均同时使用文字和图形表达。
- 对话消息流不显示团队成员或协作摘要卡；唯一例外是 3.2 定义的本轮实时工作流卡，它只表达当前 run 的执行阶段并链接权威任务，不承载成员阵容或团队进度。
- 手机端不擅自创建、解散或扩权团队；高风险动作继续使用桌面端确认与既有权限边界。
- 团队根页必须在列表前明确展示 **当前项目** 与 **来源会话** 两级范围；两者都来自 bridge/server 的权威对象，不得以标题、目录名或同名会话猜测归属。用户可清除来源会话筛选回到当前项目，但不可在未确认项目身份时混排跨项目对象。
- 每个团队列表行是完整触控目标，至少显示 `teamId` 的可辨识短段、项目/来源会话上下文、共同目标摘要、状态与最近活动；点整行进入唯一团队详情，辅助按钮不能成为唯一入口。
- 团队详情固定包含：共同目标、成员职责与当前任务、依赖/阻塞、关键时间线、产出与验证证据、可缩放协作画布。画布节点与边必须由权威 team/member/task/dependency ID 生成，支持缩放、平移、适配全图和列表式无障碍替代，不以屏幕坐标或同名对象建立关系。
- 返回团队列表时恢复 `projectId + sourceSessionId + 筛选条件 + 排序 + 滚动锚点 + 已展开成员`；从详情跳到任务/对话后再返回，也必须回到同一上下文。

### 3.4 任务域

任务域是跨执行类型的 **关注与进度中心**，不是把不同后端对象强行合并。

```text
任务
├─ 关注队列（默认）
│  ├─ 需要输入
│  ├─ 受阻
│  ├─ 待审
│  └─ 失败
├─ 进行中
├─ 已完成
├─ 筛选：代理团队 / 会话 / 类型 / 时间
└─ 任务详情
   ├─ 目标与状态时间线
   ├─ 负责人 / Agent / Team
   ├─ 依赖和阻塞原因
   ├─ 产出：文件、diff、测试、报告
   ├─ 关联对话
   └─ 允许的动作：回复、审阅、停止、重试、打开产出
```

统一展示模型：

| 展示类型 | 保留的真实身份 | 可共用字段 |
| --- | --- | --- |
| 会话 todo | 会话内计划项 | 标题、状态、关联会话 |
| Agent Team task | 持久团队任务 | 负责人、依赖、文件范围、交付物 |
| 子代理/后台作业 | 执行实例 | 运行状态、输出摘要、停止能力 |
| 定时任务 | 调度规则/运行记录 | 下次执行、最近结果、启停状态 |

- UI 可以统一排序和筛选，但根页必须提供“来源会话任务 / Agent Team / Project Tasks”可辨识分型与计数，详情页继续显示真实类型，避免把会话 todo、团队任务和项目任务合并或把“停止作业”误写为“取消团队任务”。
- “来源会话任务”入口绑定权威 `conversationId + todoId` 并回到该会话的清单/目标上下文；Agent Team task 使用 `teamId + taskId`，Project Tasks 使用项目任务处理器返回的稳定 ID。三类同名对象不得互相替代。
- 已完成默认折叠并分页；删除、归档、隐藏含义严格区分。
- 状态只来自权威宿主，断线时显示“上次同步于…”，不得继续显示未经验证的“运行中”。
- 任务根页与代理团队域使用同一 **当前项目 / 来源会话** 范围条，并允许追加团队、真实任务类型、状态与时间筛选；筛选摘要始终可见，避免用户误以为看到全局任务。
- 每个任务列表行是完整触控目标，展示权威 `taskId` 短段、真实类型、所属 `teamId`/`conversationId`、任务目标、负责人、依赖摘要与最近事件；同名任务不得合并，也不得根据标题反查归属。
- 任务详情固定包含：任务目标与所属团队共同目标、成员/负责人职责、依赖与阻塞、状态时间线、产出及验证证据、关联对话；若属于团队，还可复用同一权威图数据打开可缩放协作画布并聚焦当前任务节点。
- 返回任务列表时恢复 `projectId + sourceSessionId + 类型/状态筛选 + 分段 + 排序 + 滚动锚点`；详情中的跨域链接携带来源返回令牌，不新建第二份详情状态。

### 3.5 我的域

```text
我的
├─ 连接与设备
│  ├─ 当前电脑与线路状态
│  ├─ 已配对电脑
│  ├─ 立即重连 / 忘记电脑
│  └─ Android：手机控制
├─ 通知与关注规则
├─ 外观、语言与辅助功能
├─ 模型与插件（移动友好摘要，复杂配置可引导到电脑）
├─ 存储与隐私
├─ 更新与关于
└─ 诊断（按需展开）
```

- “连接与设备”整合散落的连接设置，但日常断线仍在当前页以内联状态恢复。
- Android“手机控制”仅在 Android 显示，并明确未设置 / 可开启 / 已开启；“立即停止”始终可达。
- iOS/iPadOS 不显示禁用空壳，也不出现“暂不支持控制其他 App”的菜单项；能力边界在配对说明和连接详情中诚实说明一次。
- 高级中继、网络实现、开发诊断默认折叠；普通用户先看到结果与恢复动作。

## 4. 页面与导航契约

### 4.1 手机框架

- 顶栏：左侧仅在二级页显示系统返回；中间为当前对象标题；右侧最多两个高频动作，其他放入“更多”。
- 内容：单列、内容驱动高度；列表行最小 Android 48 dp / iOS 44 pt。
- 底栏：四项固定，适配安全区；键盘弹出时按平台惯例隐藏或与输入区协调，不遮挡编辑器。
- 抽屉：只用于当前域的筛选/历史等补充视图，不再承载四域主导航。
- Sheet：编辑、筛选、轻量详情使用；复杂设置与任务详情使用完整页面。

### 4.2 平板框架

- 左栏为四域 + 当前域列表，主栏为详情；代理团队/任务复杂详情可在足够宽时开启第三辅助栏。
- 横竖屏切换保持选中域、对象、筛选、草稿与滚动锚点。
- 不因变宽恢复 Desktop 的全部常驻面板；仍以移动/触控任务模型为准。

### 4.3 跨端路由与状态

建议 Web 暴露稳定路由：

```text
/m/conversations
/m/conversations/:conversationId
/m/agents
/m/agents/:teamId
/m/tasks
/m/tasks/:taskType/:taskId
/m/me
/m/me/connections
```

同时提供版本化桥接契约，而非通过混淆 class 或文字定位：

- `window.HarnessMobileNavigation.version`
- `getNavigationState()` / `canNavigate(route)` / `navigate(route)` / `subscribe()`
- `subscribeAttentionCounts()`
- `subscribeConnectionState()`
- `saveDraft()` / `restoreDraft()`
- `presentSystemPicker(kind)`（由原生壳实现）
- `getCapabilities()`（如 `androidControl`、`photoPicker`、`filePicker`）

Web 使用稳定 `data-mobile-slot` / ARIA 语义作为 DOM 兜底；原生注入只做桥接和平台能力，不再重排核心页面。

团队与任务还需要版本化上下文契约：

- bridge/server 返回不可混淆的 `projectId`、`sourceSessionId`、`teamId`、`taskId`、`memberId`、对象类型、修订号与最后同步时间；显示短 ID 只用于辨识，路由和关系始终使用完整 ID。
- 列表行、详情根、上下文范围条与协作画布分别暴露 `data-mobile-object-row`、`data-mobile-object-detail`、`data-mobile-context-scope`、`data-mobile-collaboration-canvas`，并用 `data-project-id` / `data-source-session-id` / `data-team-id` / `data-task-id` 携带权威键，便于端到端验证，不把 DOM 属性当数据源。
- 返回状态由导航层保存为不透明 `returnContext`，最少覆盖域、范围、筛选、排序、滚动锚点与来源对象；对象已失效时回到原列表上下文并原位解释，不静默跳到同名对象。
- 设计预览可以使用明确标注的说明性样例数据演示层级与手势；实际产品数据必须由 bridge/server 提供。规范、实现和测试均禁止通过名称、标题、成员显示名或路径猜测同名项目、会话、团队和任务的身份或关系。
- 本轮实时工作流卡暴露 `data-live-workflow`、完整 `data-run-id` 与 `data-turn-id`；bridge/server 以这两个权威键推送阶段、当前动作、累计用时、可停止性、关联任务与总结到达事件。DOM 属性只用于契约验证，不从文案、顺序或相邻消息反推身份。
- 卡片状态机固定为 `live.compact ↔ live.expanded → archived.compact`；总结回复是进入 archived 的唯一正常终点，停止/失败也必须由权威 run 事件确认。断线时冻结用时并显示“上次同步”，不能继续本地伪造实时进度。
- 会话任务摘要与清单暴露 `data-session-task-summary` / `data-session-task-list`，持续目标暴露 `data-goal-id` / `data-goal-revision`；这些属性映射权威对象，不是移动端派生的第二份状态。
- 官方排队消息条暴露 `data-official-queue`、`data-queue-id`、`data-conversation-id` 和当前 `data-queue-revision`；编辑、删除、立即发送动作携带具体 `messageId` 调用既有队列处理器，并以服务器回执更新 UI。冲突或断线时保留原队列项并显示原因。
- 未读徽标暴露 `data-unread-badge`、`data-conversation-id`、`data-latest-message-id` 与 `data-read-state="unread|confirming|read"`。只有最新消息载入成功且 bridge/server 返回权威 read receipt 后才能切为 `read` 并移除可见计数；缓存渲染不得推进状态。

### 4.4 返回优先级

1. 关闭系统选择器或最上层对话框。
2. 关闭菜单、预览或筛选 Sheet。
3. 收起当前域内抽屉。
4. 二级详情返回所属域根页并保持列表位置。
5. 域根页再次返回：Android 进入系统退出行为；iOS 由系统导航容器处理，不自造退出确认。

Web 浏览历史不得覆盖上述产品返回栈。外链进入系统浏览器后，返回时恢复原对象。

## 5. 关键用户流程

### 5.1 首次配对并继续工作

1. 未配对启动 → 原生配对页。
2. 点击“扫描二维码”后才请求相机；拒绝时提供“打开系统设置 / 改用配对地址 / 取消”。
3. 显示“验证配对信息 → 连接电脑 → 加载工作台”的可解释状态。
4. 首次进入默认打开 **对话**；若二维码携带合法目标路由，则进入对应空间/对话/任务。
5. 非阻塞提示“已连接”，不弹成功确认框。

成功标准：正常路径从启动到可输入最多 3 个主动点击；失败路径保留配对地址并可恢复。

### 5.2 继续最近对话

1. 打开 App → 恢复上次域和对象；若对象不可用，进入对话首页并说明原因。
2. 对话首页第一组为“继续”，用户点整行进入。
3. 草稿、附件和滚动锚点恢复；网络未就绪时可继续编辑但发送按钮解释暂不可发送原因。
4. 发送后保持输入焦点；助手先给确认回复，其下出现默认紧凑的本轮实时工作流卡，权威流持续更新阶段/动作/用时并可停止或查看任务；总结回复到达后卡片自动收起归档。

### 5.3 从代理团队定位协作上下文

1. 底栏点“代理团队” → 选择真实存在的当前或最近团队。
2. 团队详情先显示共同目标、成员职责、任务状态和需要人工处理项。
3. 点关联对话或任务进入权威详情；顶部显示团队筛选标识并允许清除。
4. 返回时保持原团队、成员展开状态和滚动位置；不复制生成另一份团队数据。

### 5.4 处理“需要我”的任务

1. 任务角标提示需要处理项 → 打开任务域默认关注队列。
2. 列表直接显示原因：需要输入 / 受阻 / 待审 / 失败。
3. 进入详情查看目标、最近关键事件、影响范围和产出。
4. 主动作与状态对应：回复、审阅、打开产出、重试；破坏性停止进入确认。
5. 处理完成后该项离开关注队列，保留在进行中或已完成，不弹庆祝式阻断动画。

### 5.5 弱网与自动重连

1. 断网时保留当前内容和草稿，顶部显示单一状态条“网络已断开，恢复后会自动重连”。
2. 自动重连不堆叠 Toast，不把用户踢回配对页。
3. 超过合理时间仍不可达，提供“立即重试”和“连接与设备”。
4. 配对失效才进入阻断页，主动作“重新配对”。
5. 状态恢复后移除状态条并低频播报“已连接到电脑”。

### 5.6 Android 开启与停止手机控制

1. 我的 → 连接与设备 → 手机控制。
2. 状态驱动卡显示无障碍、通知、屏幕捕获/文件按次授权的完成度。
3. 用户主动开启“允许这台已配对电脑操作手机”。
4. 敏感动作仍逐次确认；禁止范围始终拒绝。
5. 页面与前台通知均提供“立即停止手机控制”；停止后清空待执行命令并给出明确结果。

### 5.7 设备与连接管理

1. 我的 → 连接与设备，先显示当前电脑、在线状态与上次同步时间。
2. 常用动作：立即重试、切换电脑；“忘记电脑”进入破坏性确认。
3. 线路策略与个人中继折叠在“高级连接”；普通状态不展示端口和协议堆栈。
4. 忘记后清除本机配对和登录数据，回到配对页；不得影响电脑端其他手机。

## 6. 可借鉴的“顺手”原则

以下只借鉴通用交互规律，不借鉴具体视觉表达：

1. **稳定的底部心智**：高频一级目的地始终在拇指可达区，顺序固定。
2. **列表先行**：移动端优先用可扫描列表表达对象，点整行进入详情。
3. **会话连续**：返回列表后保持位置，进入详情后保留草稿和上下文。
4. **角标克制**：只提示需要用户行动的事项，而不是把所有活动都做成红点。
5. **主次动作清楚**：一页一个主要推进动作，低频操作进入“更多”。
6. **即时但不打扰的反馈**：状态原位更新，成功不额外要求确认，错误紧邻对象并给恢复动作。
7. **渐进披露**：普通用户先完成任务，高级网络、诊断、批量管理按需展开。
8. **一致的返回预期**：关闭浮层、回详情、回列表、退出应用的层级可预测。
9. **单手与大字可用**：重要入口位于中下部或底栏，文本和触控区域不被固定高度裁切。
10. **搜索与历史不污染当前区**：完成、归档和低频对象保留可查，但不占据首屏注意力。

## 7. 禁抄边界

以下均不得照抄微信或其他竞品：

- 不复刻其底栏图标轮廓、选中态、绿色品牌色、字号、间距、分隔线和像素布局。
- 不使用“聊天 / 通讯录 / 发现 / 我”等相同功能组合；Harness 的四域必须服务对话、代理协作、任务、设备与安全。
- 不复刻聊天气泡、头像排布、消息状态符号、语音按钮、下拉小程序或朋友圈式结构。
- 不复刻“红点 + 数字”的全局焦虑式提醒；只对需要用户行动的事件建立语义角标。
- 不照搬右上角“＋”菜单项目、扫码页构图、扫一扫文案或支付相关手势。
- 不使用相同动效节奏、音效、触感序列、空状态插画和文案句式。
- 不把 Harness 的空间、任务、Agent、团队硬套成联系人、群聊或小程序隐喻。
- 不因追求熟悉感削弱 Harness 的安全确认、来源标识、任务真实状态、审计历史与平台能力边界。

原创性检查：任何设计稿在隐藏品牌后，若可被误认为微信页面，应退回重做；同时也不得以“差异化”为由破坏平台标准返回、权限和系统选择器行为。

## 8. 状态、通知与空页面

### 8.1 统一状态词汇

- 需要输入、受阻、待审、失败、进行中、已完成、已停止、上次同步。
- “运行中”只在宿主确认当前仍活跃时显示；断线后降级为“上次同步于…”。
- 相同对象的状态在四域一致，不因入口不同改名。

### 8.2 空状态

| 场景 | 标题 | 主动作 | 次动作 |
| --- | --- | --- | --- |
| 无对话 | 开始第一段对话 | 新建对话 | 选择空间 |
| 无空间 | 还没有可用空间 | 在电脑上添加空间 | 了解如何连接 |
| 无关注任务 | 目前没有需要你处理的任务 | 查看进行中 | 无 |
| 搜索无结果 | 没有匹配结果 | 清除筛选 | 修改关键词 |
| 电脑离线 | 暂时无法连接电脑 | 立即重试 | 连接与设备 |

空状态不使用虚构数据，不把网络错误展示成“空”。

### 8.3 通知

- 系统通知只用于用户明确订阅且离开 App 后仍值得打断的事项：需要输入、待审、重要失败、定时任务到期。
- 点击通知必须深链到具体对象；对象已处理时进入详情并显示最新状态，而非报错。
- 前台同一事件不重复显示系统通知和 Banner。

## 9. 无障碍、文字与触控

- iOS 支持最大辅助字号；Android 至少验证 0.85×、1.0×、1.3×、2.0× 字体。
- 所有含文字控件内容驱动高度；触控目标 iOS ≥ 44×44 pt，Android ≥ 48×48 dp。
- 每页一个清晰标题；读屏进入详情先聚焦标题，返回后回到触发行。
- 底栏暴露 tab 角色、名称、选中态和角标含义；图标不重复朗读。
- 流式生成不逐 token 播报，只播报语义段落完成、结束或需要用户行动。
- 颜色不是唯一状态编码；正文对比度至少 4.5:1，大图形至少 3:1。
- 尊重减少动态效果、增强对比度、深色模式和 RTL；所有底栏、Sheet、编辑器处理安全区。

## 10. 分期优先级

### P0：建立可信、可恢复的共同骨架

1. 定义并落地四域稳定路由、底栏、返回栈和平台能力矩阵。
2. Harness Web 提供版本化移动桥接与稳定语义槽位；Android/iOS 不再以文本和混淆 class 作为核心导航依据。
3. 对话域完成最近列表、详情、新建、草稿/附件保持和需要我处理标记。
4. 统一断线、自动重连、电脑不可达、配对失效状态；非阻断异常保留上下文。
5. 补齐相机拒绝恢复、深链失败恢复和忘记电脑闭环。
6. 四域根页、底栏、顶栏、输入区通过大字、读屏、深色、安全区和真实触控验收。

### P1：让代理团队、任务与设置真正可用

1. 代理团队域完成当前/最近团队、成员职责、任务状态、依赖和待处理项；没有真实接口时诚实禁用。
2. 任务域建立关注队列、统一展示模型、权威状态、详情与产出入口。
3. “我的”复用桌面端真实设置分类：通用、模型路由、代理团队、插件与 Skills、MCP、连接、浏览器和定时任务；Android 手机控制保留平台独占入口。
4. 打通跨域筛选和深链：代理团队 → 对话/任务，任务 → 对话/产出，对话 → 代理团队/任务。
5. iPad/大屏 Android 实现主从分栏与旋转状态保持。
6. 通知按“需要行动”聚合，完成点击深链和去重。

### P2：效率与精修

1. 跨设备导航恢复、最近搜索、固定对象和个性化关注规则。
2. 离线只读快照、草稿队列和明确的恢复/冲突处理。
3. 批量归档、历史治理、性能增量加载和长期列表虚拟化。
4. 触觉、微动效、空状态插画和品牌化视觉精修，保持原创性审查。
5. 建立移动遥测：到达可输入时间、恢复成功率、任务处理时长、误退率；不采集对话正文与敏感文件内容。

## 11. 验收标准

### 11.1 信息架构

- [ ] 已配对工作台只存在对话、代理团队、任务、我的四个一级域，顺序和语义三端一致。
- [ ] 一级域平均不超过 3 次点击到达其核心动作；新建对话、查看代理团队、处理关注任务均可单手完成。
- [ ] 同一对象只有一个权威详情页，可从其他域以关联入口到达，不重复建档。
- [ ] 原生导航栏、Web 顶栏和底栏不重复同一返回、标题或设置动作。
- [ ] 手机与平板切换不丢当前域、对象、筛选、草稿和滚动位置。

### 11.2 对话

- [ ] 冷启动有有效配对时能恢复上次可用对话；目标失效时进入可解释的对话首页。
- [ ] 最近列表优先显示需要处理和最近活动，不因低价值流式事件频繁重排。
- [ ] 新建对话在发送第一条消息前不生成空历史。
- [ ] 文本、照片、文件、截图在发送前可预览、移除、取消；失败保留草稿并可重试。
- [ ] 跨域、前后台、网络切换和键盘收起不清空草稿。
- [ ] 每轮最多一张 live 工作流卡，顺序严格为用户消息 → 确认回复 → 卡片 → 总结回复；卡片的 `turnId/runId`、阶段、动作和停止结果均与 bridge/server 权威流一致。
- [ ] 总结回复到达后卡片自动收起归档并停止实时订阅；下一轮创建新卡，消息流始终不出现成员、职责或团队摘要卡。

### 11.3 代理团队

- [ ] 列表只展示真实团队/子代理数据，并区分运行中、等待输入、受阻和完成状态。
- [ ] 团队详情能到达关联对话、任务与产出，返回后保持上下文。
- [ ] 工作台未提供团队接口时入口禁用并明确说明，不生成占位团队。
- [ ] 手机端不绕过桌面端团队权限、并发限制和高风险确认。

### 11.4 任务

- [ ] 默认关注队列只包含需要输入、受阻、待审、失败；角标与队列数量一致。
- [ ] 会话 todo、Team task、后台作业、定时任务保留真实类型和正确动作语义。
- [ ] 任务详情可到达关联对话、依赖、产出和最近关键事件。
- [ ] 断线时不继续显示未经验证的运行状态；恢复后与宿主权威状态一致。
- [ ] 已完成默认折叠、可检索和增量加载；隐藏、归档、删除不混用。

### 11.5 我的、连接与平台边界

- [ ] 配对、连接、重连、忘记电脑均有正常、加载、失败、权限拒绝和恢复状态。
- [ ] 高级线路与诊断默认折叠；普通状态先显示用户结果和恢复动作。
- [ ] Android 手机控制状态准确，“立即停止”在页面和前台通知始终可达。
- [ ] iOS/iPadOS 不展示或暗示跨 App 控制能力，也不出现禁用空壳。
- [ ] 权限按用户动作申请，照片/文件使用系统按次选择器，不请求整个图库或所有文件访问。

### 11.6 可用性与质量门槛

- [ ] iOS 最大辅助字号、Android 2.0× 字体下无关键操作裁切或不可达。
- [ ] VoiceOver/TalkBack 可独立完成配对、四域切换、继续对话、处理任务、重连和忘记电脑。
- [ ] iOS 44 pt / Android 48 dp 触控目标全部达标；无操作仅依赖滑动或长按。
- [ ] 深色、横屏、分屏、刘海/挖孔、底部手势区、键盘均不遮挡顶栏、底栏和编辑器。
- [ ] Android Emulator、iOS Simulator 至少覆盖紧凑手机与平板，并在 Android/iPhone 真机复核相机、权限、网络切换和辅助功能。
- [ ] 核心流程留存可审计证据：版本、设备、步骤、通过/失败、截图/录屏和缺陷号；证据不含配对密钥、账户、验证码或私人内容。

### 11.7 原创性验收

- [ ] 四域名称、对象模型、页面结构和状态体系可由 Harness 业务独立解释，不依赖竞品术语。
- [ ] 图标、配色、间距、消息样式、空状态、动效、触感和文案均使用 Harness 自有设计语言。
- [ ] 隐去品牌后不会被合理误认为微信或其他单一竞品页面。
- [ ] 设计评审同时记录“借鉴的通用原则”和“主动避开的具体表达”，避免后续实现回到像素模仿。

## 12. 设计完成定义

本蓝图对应的移动 IA 只有在以下条件全部满足时才算完成：

1. Android、iOS 与 Harness Web 使用同一四域路由和对象状态模型。
2. 原生壳只负责平台接入能力，共享工作台不依赖脆弱 DOM 猜测完成核心导航。
3. 对话、代理团队、任务、我的各自至少有一个可真实完成的核心闭环；缺少稳定处理器时诚实禁用，不显示占位入口。
4. 弱网、重连、配对失效、权限拒绝和平台差异都有诚实且可恢复的体验。
5. 手机、平板、大字、读屏、深色、键盘与旋转均通过可见 UI 的真实操控验证。
6. 未削弱现有配对、加密、系统选择器、敏感动作确认、Android 控制禁区与 iOS 能力边界。
7. 完成原创性评审，不复制微信或任何竞品的具体视觉与功能组合。
