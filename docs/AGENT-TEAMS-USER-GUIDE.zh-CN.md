# 代理团队（Agent Teams）用户指南

代理团队是一项**默认关闭的实验功能**。它让最外层负责人会话协调多个独立、可继续的成员会话；同一负责人还可以拥有多个平级团队，并在这些团队之间协调依赖与消息。它适合可以清楚拆分、需要并行推进的工作；如果只需要一次回答，普通会话通常更省事、也更节省模型用量。

## 先判断是否适用

**适用：**

- 一个目标能拆成研究、实现、测试、审阅、文档等相对独立的部分。
- 多个成员可以分别负责不同文件或不同只读调查，最后由负责人汇总。
- 工作持续时间较长，需要保留成员会话、任务状态和依赖关系。
- 你愿意为并行模型调用设置明确范围并关注预算。

**不适用：**

- 简单问答、一次性改动，或任务本身无法拆分。
- 多人必须同时编辑同一批文件，且没有明确的文件所有权。
- 你需要共享同一上下文窗口；团队成员拥有各自独立的上下文，并不会自动知道其他成员做过什么。
- 你希望系统自动创建 Git worktree、自动合并改动或保证没有冲突；当前版本不提供这些能力。
- 任务包含不应分发给多个模型会话的敏感内容。

## 开启与限制

1. 打开 Harness Desktop 的**设置**。
2. 进入**代理团队**设置区。
3. 开启“启用自动团队”。
4. 设置“团队成员上限”和“最大并行回合数”，然后保存。

“启用”表示从你发送的**下一条普通需求**起，让 AI 自动判断是否需要团队。开关本身只保存设置，不会伪造用户消息、自动填入提示词或立即发起团队请求；没有目标就不产生请求，也没有团队开销。简单、不可拆分的任务由使用主模型的负责人 solo 完成，只有目标明确、复杂且确实可并行时才考虑组队。

启用后，“代理团队”页顶部的“自动团队已开启”区域会显示**关闭自动团队**。没有活动团队时，点击后会立即关闭并回到未启用说明；这个设置操作不发送消息、不写入提示词、不调用模型，因此不消耗模型 Token。若存在 `active`、`closing` 等任何未关闭团队，关闭按钮会禁用并提示先让负责人完成并关闭所有活动团队；关闭实验功能不会替你中断或关停团队。全部团队关闭后即可从同一页面关闭，也可以在设置中关闭。

当前设置允许输入 1–8。`maxMembers` 是**每个团队**的成员上限；`maxActiveTurns` 是同一 root 负责人旗下**所有未关闭团队共同使用**的全局活跃回合上限，不会按团队各自重新计算，超限返回 `AGENT_TEAMS_ACTIVE_TURN_LIMIT`。宿主常量 `HARD_MAX_TEAMS_PER_ROOT` 固定为 8，因此同一 root 最多保留 8 个未关闭的平级团队；第 9 个返回 `AGENT_TEAMS_TEAM_LIMIT`，不能通过设置提高。自动模式下安全限额保持不变。数值越大并不一定越快：成员越多、并行回合越多，模型调用量和费用通常也越高。实际可用并发还可能受模型服务商、账号额度和运行环境限制。

关闭实验功能前，应先关闭仍在活动的团队。关闭功能不会改变普通 `subagent`、`subagent_fork` 或 workflow 的行为。

## 必须从最外层负责人会话开始

创建团队必须满足两个条件：

1. 当前会话是最外层的根会话，而不是子代理、团队成员或嵌套会话；
2. 当前回合由你直接发送消息触发。

因此，请回到最外层的新会话或主会话，直接说“创建一个代理团队……”。不要在成员对话中要求新建团队，也不要指望自动续轮替你创建。同一根负责人可以拥有多个平级团队，但每个团队创建后都固定由这个根会话负责；当前版本不支持转移负责人或嵌套团队。存在多个活动团队时，后续操作应明确团队名称或团队 ID。

如果系统提示必须由直接用户或根会话发起，回到最外层负责人会话，亲自重新发送请求即可。

## 推荐：像平常一样说需求

启用后无需先进入团队页，也不需要说“请创建团队”。回到“对话”，像平常一样发送下一条带有明确目标的需求即可。AI 会先判断：简单任务由负责人 solo 完成；只有复杂、可拆分且并行收益明确时才创建团队。普通用户不需要预先决定成员名称、人数、模型、职责或文件分配。

“代理团队”页里的模板只是希望立即指定协作方向时的可选入口。“自定义团队”会生成下面这种待审草稿：

```text
请创建一个代理团队来完成以下目标：<可验证的最终结果>。
请完全根据目标自行设计团队。请由 AI 判断是否需要并行、需要多少成员、
各自职责、任务依赖和互不冲突的文件边界；先建立持久任务，再创建必要成员。
不要为了凑人数创建成员。
```

“调研与核验 / 实现与审查 / 问题诊断”三个模板也只是协作方向，成员和任务仍由 AI 规划。工作目录、不能修改的内容、必须运行的检查或预算上限等硬约束可以和目标一起写明，但不要把手动设计团队当成使用前提。

开始后，可以继续用自然语言交给 AI 判断：

```text
根据当前目标和任务缺口判断是否需要增员；只有能明显减少重复工作且文件边界不冲突时才扩员，否则说明原因。
```

```text
请列出所有团队、未完成任务、跨团队阻塞和文件冲突风险，不要为了提高并行数而新增成员。
```

## 普通 subagent 与团队成员的区别

两者都使用独立上下文，但用途和生命周期不同：

- **普通 subagent**：无活动团队、且只有一个独立的一次性辅助时，root 可使用官方普通 `subagent`，例如单次检索或复核。它不是团队成员，不进入成员、任务和关停视图。
- **团队成员**：是工作区中可见、可继续、持久化的责任主体，有明确职责、正式任务、文件范围、状态和关停生命周期。

只有目标包含至少两个需委派给不同成员的持续独立工作流，且确实需要依赖、交接、文件边界或汇总协调时，才建立团队。一个辅助任务、串行工作或紧密耦合的改动继续 solo，必要时最多使用一个普通 subagent，不要为了形式创建团队。

团队成员硬性禁止调用 `subagent`、`subagent_fork`、`workflow` 或 `ralph`。需要扩员时，成员应向固定负责人报告缺口，由最外层 root 评估后创建可见的正式成员并建立持久任务；成员不能私自派生不可见助手。这项禁令防止绕过 `maxMembers` / `maxActiveTurns`、文件冲突检查、任务认领和优雅/强制关停，确保这些控制覆盖全部实际工作。

## 使用独立团队工作区

开启后，负责人会话顶部会出现 `对话 / 轨迹 / 代理团队` 视图标签。选择“代理团队”只会替换中央会话内容；左侧会话导航、顶部全局控件和底部官方输入框仍然保留。新会话仍默认打开“对话”。

当前工作区提供：

- **首次向导**：只需填写目标；可以选“自定义团队”让 AI 完全规划，也可选择“调研与核验 / 实现与审查 / 问题诊断”作为方向。AI 自行判断是否值得并行、需要多少成员、成员职责、任务依赖和文件边界。完整请求只会放入官方输入框，不会自动发送；你必须检查后亲自发送。只有系统确认这条创建草稿经历了真实提交且已成功消费，界面才会自动返回“对话”；仅点击“放入输入框”、编辑草稿或发送失败都不会切页。
- **团队总览**：同一负责人拥有多个平级团队时，可以查看活动/关闭数量、逐个切换团队，并汇总跨团队动态。快捷提示“添加协作团队”会让 AI 根据项目目标、现有团队分工和成本判断是否真的需要新的同级团队；只有职责边界清楚且能独立并行时，才自动确定新团队目标、必要成员、主/子模型分配、跨团队任务依赖和负责人中继。现有团队足够时，AI 应说明原因且不创建。切换团队或切到其他会话视图都不会停止后台成员。
- **成员区**：显示名称、角色、当前任务、运行状态和最后活动。点击“添加成员”不会要求你设计成员；它会生成一条让 AI 根据目标、任务缺口、成本和冲突自动判断是否扩员的草稿。点击“查看实时工作”进入健康成员的官方可继续会话，可实时查看输出，“轨迹”继续使用官方视图显示 Read、Edit、测试等工具时间线。
- **任务区**：显示待处理、进行中和已完成任务，以及负责人、依赖、阻塞和冲突关系。由同一固定负责人拥有的平级团队可以建立跨团队任务依赖，前置团队任务完成后才解除后续阻塞；跨根会话依赖会被拒绝。涉及非空文件范围时，Web 投影会按安全策略隐藏具体路径，完整记录仍留在宿主侧。
- **协作事件**：只显示团队中继的发送方、接收方、投递状态和时间等元数据，不展示消息正文。同一固定负责人可以在自己的平级团队之间中继消息；不同根负责人的团队默认隔离。普通团队协调消息在主聊天中折叠成低权重通知，详情和状态应在这里查看。
- **关闭摘要**：团队关闭后保留成员、任务和事件历史，并提供创建下一团队的安全提示词入口。
- **连接状态**：优先实时更新；实时连接不可用时退回轮询。

创建成员、创建或分配任务、发送团队中继、退役成员和关闭团队等敏感变更，仍应在经过鉴权的负责人/成员会话中用自然语言提出，由模型工具执行。工作区中的快捷操作只生成草稿，绝不代替你发送。切回“对话”或“轨迹”只会停止当前页面的实时监听，不会中断团队；成员会在宿主侧继续后台运行，再切回团队视图即可恢复最新状态。

## 成员、任务和消息怎么配合

### 成员

成员是独立的、可继续的子代理会话，共享同一工作目录，但上下文彼此隔离。AI 应使用“界面、测试、安全、文档”这类 **2–6 字、简单直白的职责名**，避免“宿主、协调器、执行器、实现者、子代理”等技术称谓；同时给出清楚的角色、初始任务、文件边界和完成标准。新增成员会先持久化注册，再收到正式任务；看到“等待协调员注册完成”的成员尚未开始工作，这是正常的安全流程。

### 任务

任务有三种状态：`pending`（待处理）、`in_progress`（进行中）和 `completed`（已完成）。

- 前置依赖未完成时，后续任务会显示为阻塞，不能认领。
- 认领是原子的；两个成员不会同时成功认领同一个待处理任务。
- 负责人可以分配待处理任务，也可以释放进行中任务后重新分配。
- 完成前置任务会自动解除后续任务的依赖阻塞。

建议先创建任务，再让成员开工。这样即使会话重启，也更容易看出谁负责什么、还缺什么。

### 直接打开成员对话

在工作区成员卡片中点击“查看实时工作”，会进入该成员的官方可继续会话。该入口只对已被官方会话目录发现的健康成员显示，负责人自身和仍在注册的占位成员不会显示无效按钮。这里适合：

- 补充只针对该成员的细节；
- 查看完整上下文和输出；
- 让成员暂停、修正或继续；
- 使用官方中断能力停止当前回合。

但请记住：普通聊天内容不会自动变成团队任务状态。涉及任务分配、依赖、完成状态或团队关闭时，最好明确要求更新团队任务，并回到负责人会话核对整体状态。

成员之间的团队消息通过固定负责人安全中继，来源是协调消息，不会伪装成你的直接用户消息。发送失败时不会自动重复投递；请先检查状态，再手动重发，避免重复工作。

## 多个团队与跨团队协作

同一最外层负责人可以按子目标建立多个**平级团队**，例如“研究”“实现”“发布”，但最多只能同时保留 8 个未关闭团队。它们不是嵌套团队：每个团队都有独立成员和任务，但负责人相同。每队分别受 `maxMembers` 限制，所有团队的活动回合合计受同一个 `maxActiveTurns` 限制。团队总览用于切换和观察，不会因为离开当前团队页面就暂停其他团队。

- 不确定是否应该拆出新团队时，点击“添加协作团队”。它只生成待审草稿，不会直接创建；AI 必须先比较项目目标、现有分工、重复工作和成本。现有团队已足够时应停止并说明原因。
- 确需新增时，由 AI 自动定义同级团队目标、必要成员、主/子模型选择、跨团队依赖和共同负责人中继；用户不需要填写一套团队设计表。
- 多个团队同时活动时，要求状态、发消息、分配任务或关闭团队都应带团队名称或 ID，避免歧义。
- 同一负责人可以让一个团队的任务依赖另一个团队的任务；工作区会把未完成的跨团队前置任务显示为阻塞。
- 只有这个共同的固定负责人可以向另一个平级团队中继消息，并且必须明确来源团队和目标团队。
- 不同根会话拥有的团队默认隔离：不能建立跨根依赖、不能跨根中继，也不能把一个根的成员挂到另一个根的团队。
- 成员仍只属于自己的团队；需要跨团队协调时由负责人汇总最小必要信息，不要假设成员自动共享上下文。

示例：

```text
在“实现团队”创建“集成”任务，让它依赖“研究团队”的“接口核验”任务；
由共同负责人把核验结论中继给实现团队。不要连接其他根会话的团队。
```

## 避免文件冲突

所有成员默认共享工作目录，当前版本**不会自动创建 Git worktree，也不会自动合并**。任务里的文件范围只是协调和预警机制，不是文件锁。

推荐规则：

1. 给每个可写任务列出规范化文件路径。
2. 同一文件同一时间只允许一个成员拥有写权限。
3. 审阅者只读检查，通过团队消息提出修改建议，由文件负责人落盘。
4. 工作台出现文件冲突风险时，先暂停其中一个任务；不要让双方继续写后再“碰碰运气”合并。
5. 让负责人在汇总前检查版本控制差异和测试结果。

仅当你自己已经准备并分配了独立 worktree 时，才让成员使用不同 worktree；代理团队不会替你完成这一步。

## 模型选择策略

代理团队直接复用 Harness Desktop 现有的**主模型与子代理**路由，不增加第二套“团队模型”设置：

- 固定负责人是团队的规划与汇总“大脑”，始终使用当前主模型，不会为了省成本自动降级到子代理模型。
- 团队成员由 AI 按任务内容在已配置的主模型和子代理模型之间选择。普通实现、检索、整理、测试等任务默认使用子代理模型，以减少成本。
- 高复杂推理、总体架构、安全关键决策，或成员使用子代理模型失败后需要升级处理时，AI 才应为该成员选择主模型。
- 如果你没有单独配置子代理模型，成员自然继承主模型；这不是错误，也不需要额外设置。
- 请在现有“设置 → 模型 → 主模型与子代理”中选择路由。团队工作区不会再提供重复的 Provider、模型或密钥配置 UI。

AI 的选择是成本与任务风险之间的默认策略，不是精确费用保证。若你有模型合规、可用区或预算硬约束，请直接写进团队目标，让负责人在创建成员前遵守。

## 成本与并行度

每个成员都有独立上下文，通常会产生独立的输入、输出和工具调用用量。负责人汇总、成员间中继、失败重试也可能增加用量。因此，不能只用“成员数 × 一次对话”估算成本，当前产品也不承诺某个精确金额。

降低成本的方法：

- 从 1–2 个成员和较低并行度开始，再按需要增加。
- 给成员窄而明确的范围，避免多人重复读完整代码库或重复研究。
- 先做短调查任务，再决定是否值得进入实现。
- 用任务依赖延后暂时不能开工的成员。
- 完成后及时退役成员并关闭团队。
- 在模型服务商的用量页面查看实际 Token、额度和计费；工作台提示只用于提醒，不是账单。

## 成员失败与替换

成员可能因为模型、网络、并发限制、进程重启或任务说明不足进入 `failed` 状态。系统不会悄悄创建替身，也不会自动重放不确定是否送达的消息。

建议在负责人会话中按以下顺序处理：

1. 要求查看团队状态、失败原因、该成员最后的报告和已修改文件。
2. 如果成员仍在运行，先中断；随后优雅退役。无法响应时再请求强制退役。
3. 将它占用的进行中任务释放回待处理；保留已完成且已核验的任务记录。
4. 创建一个新的具名成员，并重新分配待处理任务。不要假设新成员继承旧成员上下文；在新提示中写明必要背景和文件现状。
5. 重新检查文件差异和测试，确认旧成员没有留下半成品。

可直接对负责人说：

```text
成员“实现者”失败了。先检查它的状态和文件改动；释放它的进行中任务，优雅退役。若无法响应则强制退役。然后创建“实现者-替补”，把未完成任务和必要背景重新交给它，不要重复已核验的成果。
```

## 优雅关闭与强制关闭

**优雅关闭是默认选择。** 负责人会请求成员完成必要清理、提交最终报告并停止接收新工作。先确认任务已完成或明确放弃，再在负责人会话中说：

```text
请先收集所有成员的最终报告，确认没有进行中任务，然后优雅关闭整个团队。
```

如果只想移除一个成员，可以要求“优雅退役成员 `<名称>`”。优雅请求发出后，成员可能暂时显示为正在关闭；等待它结束并再次检查状态。

**强制关闭只用于成员卡死、负责人无法等待或优雅关闭反复失败。** 它会中断成员及其后代回合，可能来不及报告、清理或保存未落盘工作。强制操作后仍应检查工作目录和任务状态。

如果关闭部分失败，团队可能保持活动以便重试，而不是假装已经完全关闭。请查看失败列表，处理对应成员后再次关闭。

## 孤儿团队恢复

“孤儿团队”是指原最外层负责人已不可用，但持久化团队记录仍未关闭。恢复不是接管负责人，也不会继续原团队；当前能力是由**另一个最外层根会话中的直接用户回合**检查候选记录，并在确认后关闭安全的孤儿团队。

处理步骤：

1. 新建或打开一个最外层根会话。
2. 直接要求“检查可恢复的孤儿代理团队”，先只预览，不确认变更。
3. 核对团队 ID、成员和任务。
4. 确认所有工作成员都不再处于配置中、运行中或关闭中。
5. 再明确要求确认恢复/关闭指定孤儿团队。

如果仍有活动成员，系统会拒绝恢复关闭。此时不要绕过检查；先设法停止活动会话，或保留记录等待其变为非活动状态。

## 常见问题

### 为什么启用后没有立即创建团队？

这是正常行为。开关不发送消息，也不会在没有目标时制造请求；自动判断从你下一条普通需求开始。若需求简单或不适合并行，AI 会保持 solo，不会为了展示功能而强行组队。

### 为什么我说“创建团队”却被拒绝？

常见原因是功能未开启、当前不是最外层根会话，或消息不是你在当前回合直接发送。依次检查设置和会话层级。同一负责人可以创建多个平级团队；如果后续操作提示目标不明确，请明确团队名称或团队 ID。

### 为什么成员一直说在等待注册？

成员的第一回合只用于安全注册，注册持久化后才会收到正式工作说明。短暂等待是正常的；长时间不变化时，让负责人检查成员状态，不要直接要求等待中的成员自行开工。

### 为什么任务无法认领？

任务可能已有负责人、不是待处理状态，或仍被未完成的前置任务阻塞。让负责人列出 `blockedBy` 和当前负责人，再完成依赖或释放任务。

### 为什么工作区不能直接添加成员或修改任务？

团队状态投影是只读的。工作区里的“添加成员、添加协作团队、创建任务、协调团队、请求关闭”等快捷按钮只会把建议提示词放入底部官方输入框，不会自动发送或绕过权限。“添加协作团队”也可能得到“不需要新增”的结论。请先检查草稿，再由你亲自发送；真正的变更仍由经过鉴权的团队工具执行。

### “协作事件”为什么看不到正文？

Web 工作区只展示投递元数据，完整内容留在经过鉴权的会话中。点击“查看实时工作”打开对应成员会话，或让负责人汇总；不要把“协作事件”当作完整聊天记录。

### 为什么点击“放入输入框”后没有自动回到“对话”？

这是有意的安全行为。生成或编辑草稿不算发送；只有创建请求真实进入提交阶段、成功结束且官方输入框已消费草稿后才自动返回“对话”。发送失败或取消时继续留在团队页，避免误以为已经创建成功。

### 切到其他团队或页面会停止成员吗？

不会。普通切页只卸载当前 UI 的 SSE/轮询订阅，不会调用中断、退役或关闭。团队会在宿主侧继续工作；再次打开团队页会读取最新状态。

### 文件冲突警告会阻止写入吗？

不会。它只是根据进行中任务声明的重叠文件范围发出警告。真正的隔离需要你分配不同文件，或自行准备独立 worktree。

### 重启后团队会消失吗？

团队、任务和成员会话是持久化的；成员会话可继续。重启时处于短暂状态的成员会被校正为可恢复或失败，不会把“正在运行”当成确定事实。重启窗口内投递状态不确定的消息会标为失败，需人工确认后重发。

### 可以同时有多个团队、多个负责人或转移负责人吗？

同一最外层负责人可以同时拥有多个平级团队，但最多 8 个未关闭团队，且**每个团队仍只有这个固定负责人**。每队成员受 `maxMembers` 限制，所有团队共享 `maxActiveTurns`。当前不支持团队内多负责人、领导权转移或嵌套团队；不同根负责人的团队也不能互相连接。

### 关闭团队会删除历史吗？

不会把未完成任务从历史记录中抹掉；成员会话仍使用官方会话机制保存。关闭的重点是停止活动成员并结束团队生命周期。

## 最稳妥的日常流程

1. 在设置中开启功能，并设置较小的成员与并行上限。
2. 从最外层负责人会话打开团队页，只填写目标，让 AI 判断是否需要团队并规划必要成员。
3. 检查草稿后亲自发送；成功提交后界面自动返回“对话”。
4. 让 AI 先建持久任务、依赖和文件范围，再添加必要成员；有独立子目标时可建立同根平级团队。
5. 用团队总览观察各团队、跨团队阻塞、投递状态和冲突风险；普通切页不影响后台工作。
6. 需要细节时直接打开成员会话；跨团队协调、状态变更和关闭都由共同负责人执行，并明确团队 ID。
7. 负责人核验差异、测试和最终报告，随后优雅退役成员并关闭团队；只有卡死时才强制关闭。
