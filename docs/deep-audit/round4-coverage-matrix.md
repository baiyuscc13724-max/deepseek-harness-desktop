## 2. 用户最高优先项的结论（可复核）

- **延迟形态**：在夹具建模的受限链路上，**整块快照在途时，后续命令的 ACK 被阻塞到整块下载完成**（P50≈P95≈max≈7.79s）；**分页把在途字节数压到一页，P50 降到 0.32s**。
- **分段归属**：98.9% 的等待落在 `ackRelayQueue` 一段，其余分段（请求侧、回执后段）均在毫秒级。
- **代价**：同样字节的完整下载因分页 **+50%**。
- **独立性 145/145 上行、107/107 下行，0 丢/0 重/0 乱序；中断在 137.8ms 内失败且旧缓存字节不变。**
- **委派不可用**（与本项无关但同属"用户体验"）：子会话被派发到 `openai-codex` 并在传输层 `fetch failed`（**7/7 子会话、每个 turn**），而根会话实际由 `opencode-go-v41/deepseek-flash` 服务；**团队代码 146 项全绿**说明故障在传输层而非团队逻辑。

## 4. 我撤回的两个说法（诚实记录）

1. **"7.7 秒来自真实 relay 缓冲"**——撤回。该数字来自夹具自建的受限链路模型；我用**真实 ws 套接字**尝试复现背压，得到**负向结论**：loopback 上即使暂停消费者，`bufferedAmount` 也不增长到边界，故**真实传输端到端背压在本环境不可复现**。
2. **"113px 白带是最具体的白栏候选"**——撤回。回执实测 `guest.sidebar` 为 `x=0,width=280,height=930`，该带区**完全落在侧栏内部**（其白色背景右半部分），且**没有任何元素从 x=166 开始**，也没有元素右边界为 166。它是良性布局，不是缺陷。

## 5. 环境未覆盖项（明确列出）

- **真机 / 公网 WAN / 真实 LLM / 完整 Host**：全部未验；手机链数字来自**合成链路模型**。
- **真实 OS 剪贴板**：未验（交互套件用虚拟剪贴板）。
- **用户白栏**：**未复现、未归因**。已收窄为间歇性 `blink.mojom.Widget` 消息拒绝（29 份日志中 3 次≈10%，且**每次所在运行都通过**），三次复现相位**不一致**（两次启动、一次中段）。**缺少用户原截图，无法比对。**
- **下载中切换 profile**、**连续超时/重试预算耗尽**：无对应用例。
- **可访问性的真读屏器/系统级辅助技术**：未验。
- **核心升版（第 ③ 项）**：施工计划已备（`core-upgrade-execution-plan.md`），**未开工**；理由见计划第 0 节（中途停下会毁掉刚恢复的验收能力）。

## 7. 终局发现的验收冲突（必须与前文并列阅读）

**第三轮已验收证据门在终局复核时为 72/73，不再是 73/73。** 唯一失败断言：

```
NO explicit historical mapping: round3-independent-fixed-closure
scripts/verify-static.mjs ef5682bb8a95680e…
```

- `ef5682bb…` 是 `scripts/verify-static.mjs` 的**编辑前字节**（本会话最早的 `deep-audit-core-compat/source-before.json:8` 即记录此值）；我为了让**发布静态门**在 1.0.60 候选上通过而编辑了该文件，故该闭包（钉住 6571 个文件）不再匹配。**这是我造成的，已如实登记。**
- **闭包机制**（`.artifacts/.../integration/integrity.cjs:11-13`）：文件漂移时查 `source-remap-v2/mapping.json` 的 `{file, sha256, originalBytes, manifests}`；安装器另有 `before-v2/mapping.json` 特例。该文件第 11 行**硬断言映射条目数 = 16**。
- **修复需一次新的验收决定**：新增一条把 `ef5682bb…` 映射到归档原件的条目，并**同步把计数 16 改为 17**。**材料齐备**：归档原件 `.artifacts/deep-audit-question-delivery/before-v2/original/scripts/verify-static.mjs` 的哈希正是 `ef5682bb8a95680e…`。
- **未擅自处理**：那是验收证据基础设施，自行加条目与改计数等于改写已验收证据的口径。上一轮建立该机制时属于**当时新开的一轮验收**。

**因此这是一处真实的门与门不兼容**：同一个 1.0.60 候选**无法同时**满足 (a) 发布静态门通过（要求编辑 `verify-static.mjs`）与 (b) 第三轮闭包字节不变（`ef5682bb…`）——除非加入上述**记录的、计数同步更新**的映射。
