# 移动性能基线与验收

本验收套件面向 MuMu/ADB 实测，独立于实现代码，不修改产品文件。测试契约位于 `tests/mobile-performance-acceptance.test.cjs`，采集器只需输出同名字段后调用 `evaluateRun()`。

## 运行

```powershell
node --test tests/mobile-performance-acceptance.test.cjs
```

在真实设备上，先固定设备型号、分辨率、Android 版本、电池状态、网络配置和应用版本；每个场景至少重复 5 次，记录中位数与 P95。冷启动需强制停止并清理进程（不清除应用数据），热启动仅返回桌面后再次打开。时间均使用单调时钟，从用户动作前一刻开始，到页面出现可操作控件为止。

## 阈值（P95）

| 指标 | 通过阈值 | 采集终点 |
| --- | ---: | --- |
| 冷启动 | ≤ 2500 ms | 首个项目可操作 |
| 热启动 | ≤ 1200 ms | 首个项目可操作 |
| 首个项目可见 | ≤ 1800 ms | 项目标题和编辑入口可见 |
| 权威刷新 | ≤ 2500 ms | 权威数据替换缓存并可见 |
| 断网恢复 | ≤ 5000 ms | 恢复连接且状态可操作 |
| LAN/P2P/Relay 单阶段 | ≤ 12000 ms | 阶段成功或明确失败 |
| 500/2000/10000 字提交 | ≤ 800 ms | 文本提交完成、无丢字 |
| IME 开合 | 各 ≤ 1200 ms | 布局稳定 |
| 工具栏位移 | ≤ 4 px | IME 开合前后 |
| IME 掉帧 | ≤ 3 帧 | 一次开合周期 |

## 可重复场景矩阵

1. **cold-start / hot-start**：冷启动强停应用；热启动从桌面打开。分别记录启动、项目可见、首个可操作事件。
2. **cache-hit / authority-refresh**：首次加载记录 `cacheState=miss`，随后重复加载记录 `hit`；断网时显示缓存，恢复后必须记录 `refreshMode=authority`，确认权威版本号/更新时间替换缓存，不能把缓存命中冒充权威刷新。
3. **offline-recovery**：进入项目后切断网络，确认页面仍可读；恢复网络，记录从网络恢复到连接状态可操作的时间，并检查没有重复消息或错误覆盖。
4. **connection-stages**：逐次记录 `lan`、`p2p`、`relay` 的开始/结束时间；失败阶段必须有原因，不能把总耗时伪装为单阶段成功。MuMu 可用固定 LAN 隔离和受控外网配置复现。
5. **long-input**：分别输入 500、2000、10000 字多行文本，提交并回读长度、首尾片段和换行数；记录提交时延、是否截断/丢字、滚动位置。
6. **ime-stability**：中文输入法开合各 5 次，记录可视区域高度、编辑框底边、工具栏位置和掉帧；工具栏必须保持独立行，不遮挡编辑框或发送按钮。ASCII 与中文各执行一次；中文输入应通过设备已选 IME，不使用绕过路径。

## 失败诊断

- 启动超时：导出应用日志、启动阶段事件时间戳、设备 CPU/内存；区分进程启动、首屏绘制、项目可见。
- 刷新失败：保留缓存版本、权威版本、网络切换时间与连接路径；确认是否误报 cache hit。
- 连接失败：保留每阶段开始/结束、错误码及最终路径（LAN/P2P/Relay），不得只报总耗时。
- 长文本失败：记录期望/实际 UTF-16 长度、Unicode 码点长度、换行数、首尾 80 字符；确认是否输入法或渲染层截断。
- IME 失败：记录开合前后窗口尺寸、编辑框/工具栏坐标、掉帧数和截图；若无法稳定复现，至少保留 5 次原始样本。

通过条件是所有必需场景存在且全部阈值通过。任一测量缺失、缓存/权威模式未明确、连接阶段未拆分，均判失败而不是跳过。测试文件中的 `healthyRun()` 仅用于契约自检，不代表真实设备结果。
