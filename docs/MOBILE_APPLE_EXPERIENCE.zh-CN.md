# Harness Mobile：Apple HIG 产品与体验规范

> 适用范围：`mobile/ios` 与 `mobile/android` 的手机和平板体验。本文以 Apple Human Interface Guidelines 的清晰、克制、一致、直接操控原则为基准，同时保留 Android 平台惯例。  
> 规范级别：**必须**为发布阻断项，**应**为默认实现，**可**为增强项。本文只定义体验，不改变现有安全、网络和平台能力边界。

## 1. 设计目标与不可突破的边界

### 1.1 核心任务

用户应能以最少决策完成以下闭环：

1. 在 Desktop 打开“手机同步”。
2. 用手机扫描一次性二维码，或粘贴配对地址。
3. 看懂正在使用局域网还是加密远程线路，并在异常时知道系统是否会自动恢复。
4. 进入与 Desktop 同源的工作台，继续对话和管理会话。
5. 随时查看连接设置、重连或忘记电脑。
6. 仅在 Android 上，按需开启并随时停止“手机控制”。

### 1.2 平台能力边界

- **iOS/iPadOS 必须明确只控制 Harness 工作台本身**；不得暗示能读取、点击或输入其他 App。不得展示 Android“手机控制”的空壳入口。
- **Android 可提供手机控制**，但无障碍、通知、屏幕捕获、文件选择及敏感动作确认必须保持逐级、按需授权。
- 配对资料的安全存储、局域网优先、WSS/443 端到端加密后备、系统 VPN 不被替换等既有承诺不得被视觉简化成不准确表述。
- iOS 更新只进入 App Store/TestFlight；Android 更新仍须由系统核验签名并由用户确认安装。
- 自动重连不是“永远在线”：iOS 前台连接限制和网络切换应以诚实文案说明。

## 2. 现状审计摘要

### 2.1 已有优势

- iOS 已使用 `NavigationStack`、系统按钮、确认对话框和动态系统色，基础行为接近平台惯例。
- 两端均以扫码为主操作、粘贴地址为后备，并保留已配对电脑自动重连。
- Android 已有独立连接遮罩、扫码退出路径、连接设置、忘记电脑二次确认，以及分步骤的手机控制授权页。
- Android 工作台已将桌面侧栏适配为底部操作区，并对对话、设置弹层和输入区做窄屏处理。
- 连接和安全文案总体诚实，未掩盖局域网、远程后备、系统 VPN 与平台能力差异。

### 2.2 发布前优先修正的体验缺口

| 优先级 | 现状 | 风险 | 规范结论 |
| --- | --- | --- | --- |
| P0 | iOS 扫码相机被拒后直接退出，无原因和“前往设置”入口 | 用户无法恢复 | 必须显示权限解释页，并提供“打开设置”“改用配对地址”“取消” |
| P0 | iOS 连接失败主要复用正文状态文字；工作台加载失败直接触发重试 | 状态层级和可恢复动作不清 | 必须采用明确错误状态：标题、原因、主恢复动作、次操作 |
| P0 | Android DayNight 主题仍固定浅色 token，状态栏固定浅色图标策略 | 深色模式对比度可能失效 | 必须提供 `values-night`/语义色或等效实现，并随主题更新系统栏外观 |
| P0 | Android 多数界面文案硬编码在 XML/Java | 本地化、无障碍与一致性难维护 | 所有用户可见文案必须进入字符串资源；动态文案使用占位符 |
| P1 | iOS 与 Android 工作台移动适配不完全同源；iOS 未见 Android 的注入式移动适配 | 两端结构和触控体验可能分叉 | 工作台必须共享同一移动 IA/响应式契约，平台壳仅处理导航、权限与系统行为 |
| P1 | Android 连接遮罩以整屏阻塞呈现，重连按钮图标语义实际包含“连接设置” | 长时间等待焦虑；图标含义不符 | 连接中可保留上下文；入口命名统一为“连接设置”，图标不得表达“撤销/重新配对” |
| P1 | Android 手机控制页用手工“‹ 返回设置”和编号卡片 | 与系统导航及完成度状态不一致 | 使用系统返回/顶部应用栏；步骤以状态而非固定编号驱动 |
| P1 | 固定字号、固定高度和多处单行布局 | 大字体截断、控件变形 | 必须支持 Dynamic Type/系统字体缩放至最大辅助字号，不以固定高度锁死文本控件 |
| P1 | 连接进度和动态状态没有明确的读屏播报策略 | VoiceOver/TalkBack 用户不知道状态改变 | 状态容器必须为合并语义区域，并以克制的 live announcement 播报关键转折 |
| P2 | 品牌、页面标题、“Desktop/电脑/桌面工作台”混用 | 用户心智不稳定 | 产品名保留 DeepSeek Harness；对象统一称“电脑”，功能统一称“Harness 工作台” |

## 3. 信息架构

### 3.1 顶层结构

应用只保留三个顶层目的地，不增加通用 Tab Bar：

1. **配对**：未保存有效配对时的根页面。
2. **工作台**：已保存配对后的默认根页面；内容为 Harness Web 工作台。
3. **连接设置**：从工作台顶部“更多”菜单进入的模态页/推入页，包含连接状态、重连、忘记电脑；Android 另含“手机控制”入口。

理由：用户主要任务是进入一个工作台，不需要在多个平级模块间频繁切换。底部栏只属于工作台 Web 内容自身，不与原生 Tab Bar 叠加。

### 3.2 导航层级

```text
应用启动
├─ 无有效配对 → 配对
│  ├─ 扫描二维码（全屏模态）
│  ├─ 手动输入配对地址（配对页内展开）
│  └─ 配对成功 → 工作台
└─ 有有效配对 → 恢复连接 → 工作台
   ├─ Web 工作台内导航
   └─ 原生连接设置
      ├─ 立即重连
      ├─ Android：手机控制
      └─ 忘记这台电脑（破坏性确认）→ 配对
```

### 3.3 手机与平板

- **iPhone/窄屏 Android**：单列；工作台侧栏作为抽屉，常用目的地置于底部工作台栏。
- **iPad/宽屏 Android（建议断点 700 pt/dp）**：使用分栏。会话列表为可折叠侧栏，当前会话为主栏；详情只在空间足够时显示，不得单纯隐藏关键能力。
- 旋转时必须保持当前会话、输入草稿、滚动位置及已打开的设置层级。
- 不允许原生导航栏、Web 顶栏和 Web 底栏同时重复展示同一“设置/返回”动作。

## 4. 首启与配对流程

### 4.1 配对首页

从上到下采用以下结构：

1. 小型产品标识，不承担可点击操作，读屏忽略装饰图。
2. 大标题：**“连接到 Harness Desktop”**。
3. 说明：**“在电脑上打开‘手机同步’，然后扫描一次性二维码。”**
4. 主按钮：**“扫描二维码”**，使用系统二维码图标。
5. 次按钮/披露控件：**“改用配对地址”**。
6. 展开后显示多行地址输入框和按钮 **“连接”**。
7. 底部隐私与线路说明：**“优先使用局域网；不可达时自动尝试端到端加密的远程线路。”**
8. iOS 额外说明：**“iPhone 和 iPad 只能访问 Harness 工作台，不能控制其他 App。”**

实施要求：

- 主按钮在可视首屏内；输入框默认折叠，避免与扫码竞争。
- 扫描和粘贴是同一任务的两种方式，不做两个同权主按钮。
- 配对地址输入使用 URI 键盘、关闭自动更正与自动大写，并允许系统粘贴。
- 输入内容前后空白应自动清理；不要在用户键入过程中持续报错。
- 点击“连接”或键盘“连接/前往”后才校验；错误紧邻输入框，并把焦点移至错误摘要或输入框。
- 深链进入时直接进入“正在验证配对”状态；失败后回到配对页并保留可编辑地址，不出现空白页。

### 4.2 相机授权与扫码

- 首次点“扫描二维码”后才请求相机权限，不在应用启动时申请。
- 权限前置说明只解释当前价值：**“需要使用相机扫描电脑上的一次性配对二维码。”** 不宣传泛化能力。
- 扫码页为全屏沉浸式模态：左上角系统“关闭/取消”，中央明确取景框，底部一句指引。
- 成功识别后提供轻触觉反馈，并立即关闭扫码页；不得蜂鸣或重复提交。
- 无法识别 8 秒后可显示非阻塞提示：**“请调亮电脑屏幕，并将完整二维码放入框内。”**
- 相机被拒或受限时，不得静默返回。必须显示：
  - 标题：**“无法使用相机”**
  - 正文：**“你仍可粘贴电脑上显示的配对地址。”**
  - 主操作：权限可恢复时为 **“打开系统设置”**
  - 次操作：**“改用配对地址”**
  - 取消：**“取消”**
- VoiceOver/TalkBack 下不得依赖实时相机画面完成任务；“改用配对地址”必须始终可达。

### 4.3 配对验证与成功

状态顺序应稳定为：

1. **正在验证配对信息…**
2. **正在连接电脑…**
3. 有后备线路时：**正在尝试局域网；不可达时会自动切换加密远程线路…**
4. 成功后进入工作台，不额外弹成功对话框；首次成功可用短暂、非阻塞提示 **“已连接”**。

配对失败必须区分：

- 地址无效：**“配对地址无效。请在电脑上重新生成二维码。”**
- 配对已过期/401/403：**“配对已失效。请在电脑上重新生成二维码。”**
- 安全存储失败：**“无法安全保存配对信息。请稍后重试。”**
- 当前无网络：**“当前没有可用网络。网络恢复后会自动重试。”**
- 电脑不可达：**“暂时无法连接电脑。请确认 Harness Desktop 正在运行。”**

错误不应暴露 URL、端口、异常类名或内部线路实现；诊断信息可进入可复制的日志入口。

## 5. 主工作台

### 5.1 原生壳

- iOS 使用系统 Navigation Bar；标题显示当前工作区/会话，空间不足时单行尾部截断。
- Android 使用符合 Material 平台行为的顶部应用栏；系统返回优先关闭 Web 弹层、抽屉或键盘，再回到连接设置，不把历史配对重定向当浏览器历史。
- 右上角统一为“更多”菜单，至少包含：**“连接设置”**；Android 可包含 **“手机控制”**。不要把“忘记电脑”直接暴露为常驻主按钮。
- 工作台加载时优先保留上一次可见内容，并在顶部显示细进度或状态条；仅首次无内容时使用居中占位。
- 原生壳不得覆盖 Web 的输入区、底部安全区或系统键盘。

### 5.2 Web 工作台移动契约

- 页面结构必须以语义槽位稳定表达：会话、侧栏、标题、编辑器、设置、日志；移动适配不得依赖易变的混淆 class 名作为唯一选择器。
- 最小交互目标：iOS 44×44 pt；Android 48×48 dp。相邻目标至少留 8 pt/dp 的有效间距。
- 输入框正文字号不得小于 16 pt，避免 iOS 聚焦缩放；支持多行增长，但最多占可用高度的 40%，之后内部滚动。
- 工作台底部栏加上 `safe-area-inset-bottom`；抽屉和全屏设置加上顶部、底部、左右安全区。
- 会话列表项整行可点，至少 48 pt/dp 高；选中态同时使用形状/背景和语义状态，不只靠颜色。
- 设置应表现为 iPhone 全屏 sheet、iPad form sheet/分栏、Android 全屏或大屏对话页；关闭动作固定且读屏可识别。
- 外部 HTTP(S) 链接交给系统浏览器，并在离开应用前保持用户上下文；不支持的 scheme 显示可恢复错误。
- Web 内容必须跟随系统文本缩放、深色模式、减少动态效果和增强对比度偏好。

### 5.3 键盘与焦点

- 键盘出现时编辑器随键盘上移，不通过缩放整个 WebView 规避遮挡。
- 交互式下滑可收起键盘；发送后焦点默认留在编辑器，除非打开新页面。
- 外接键盘支持：Tab 顺序符合视觉顺序；Escape 关闭最上层菜单/对话框；Command/Ctrl+Enter 是否发送必须与 Desktop 一致并在设置中说明。
- 打开设置或连接错误时保存输入草稿；重连不得清空未发送文本。

### 5.4 文本、照片、文件与截图发送

聊天输入区必须在 iPhone、iPad 与 Android 上提供同一组用户可发现的输入能力：输入或粘贴文本、从相册选择照片、从系统文件选择器选择文件，以及主动截取并发送当前 Harness 工作台画面。附件能力属于聊天编辑器，不放入连接设置或 Android 手机控制。

#### 5.4.1 入口与交互

- 编辑器左侧提供带文字替代标签 **“添加附件”** 的单一附件按钮，点击后显示平台原生菜单：**“照片”**、**“文件”**、**“截取当前工作台”**；不把三个小图标永久挤在输入框旁。
- 附件按钮、每个菜单项、预览移除按钮和发送按钮的触控区域在 iOS 至少 44×44 pt，在 Android 至少 48×48 dp；大字体下菜单项可换行但不可裁切。
- 文本支持系统键盘输入、硬件键盘输入、长按粘贴与系统剪贴板粘贴。粘贴图片或文件时走同一附件预览流程；粘贴普通文本不得弹额外确认。
- “截取当前工作台”只响应用户本次点击，只捕获当前 App 前台可见的 Harness 工作台内容；不得后台截屏、定时截屏或捕获其他 App。截取后先进入预览，未经再次点击“发送”不得上传。
- 用户刚通过系统截图功能保存的图片必须能通过“照片”系统选择器主动选取；App 不得轮询“最近项目”或因检测截图而自动读取/上传。
- 选择器返回后焦点回到编辑器附件区；取消选择不得清空已输入文本或已有附件。

#### 5.4.2 最小权限与数据边界

- **iOS/iPadOS**：照片使用系统 Photos Picker/PHPicker 等按次选择界面，文件使用系统 Document Picker；仅访问用户明确选择的项目。不得为了发送附件请求整个照片图库权限。
- **Android**：照片优先使用系统 Photo Picker，文件使用 Storage Access Framework 的按次选择；不得申请“所有文件访问”、整个媒体库或整个存储空间权限。
- 不在应用启动、进入工作台或聚焦输入框时预先申请照片、文件或屏幕能力；权限/系统选择器只由明确的附件操作触发。
- 选中文件的临时访问只保留到预览、上传完成或用户取消所需的最短时间；取消、发送完成和失败放弃后应释放临时副本与不再需要的 URI 授权。
- 预览只读取生成缩略图和显示名称/大小所需内容；不得后台索引相册、枚举目录、读取未选择项目或将附件用于训练、分析等发送之外目的。
- 发送前后的传输与落盘沿用 Harness 既有安全边界；界面不得以“已加密”等未经当前链路验证的笼统徽章代替真实状态。

#### 5.4.3 预览与发送状态

附件在真正发送前显示于编辑器上方的可横向滚动/换行预览区：

- 图片/截图：缩略图、可读文件类型或“截图”标签、移除按钮；点缩略图打开大图预览，关闭后回到原焦点。
- 普通文件：类型图标、完整文件名的可访问名称、易读大小；视觉上可截断文件名，但读屏名称必须完整。
- 多附件按选择顺序排列；发送前可逐项移除，移除最后一项不影响文本草稿。
- 发送按钮仅在存在非空文本或至少一个有效附件时启用；文本与附件可在同一条消息中发送。
- 用户点击发送后，每项进入 **“正在准备”→“正在上传”→“已发送”**；有真实字节进度时才显示百分比，否则显示不确定进度和文字状态。
- 消息发送成功后才清空对应文本和附件；若仅部分附件失败，已成功内容不得重复发送，失败项留在编辑器或消息失败区供单独处理。

#### 5.4.4 取消、失败与超限

| 状态 | 呈现 | 可用操作 |
| --- | --- | --- |
| 系统选择器取消 | 静默返回原草稿，不显示错误 | 继续编辑 |
| 正在准备/上传 | 预览项内显示状态，不阻塞整个会话 | 取消上传 |
| 用户取消上传 | 停止网络与临时处理，保留可重新选择的明确结果 | 移除 / 重试（仍有授权时） |
| 类型不支持 | 预览项内错误：**“不支持此文件类型”** | 移除 / 重新选择 |
| 单文件超限 | 选择后、上传前提示实际限制：**“文件超过 {limit}，请选择较小的文件”** | 移除 / 重新选择 |
| 数量超限 | 保留允许范围内的选择并说明实际数量限制 | 管理附件 |
| 本地读取失败 | **“无法读取所选文件”**，不暴露 URI 或路径 | 重试 / 移除 |
| 网络中断 | 保留草稿和附件预览，说明网络恢复后是否自动继续 | 重试 / 取消 |
| 服务端拒绝 | 显示映射后的原因；原始诊断只进日志 | 重试 / 移除 |

- 文件类型、单文件大小、总大小和数量限制必须由当前产品/服务能力提供并在选择后立即预检；不得在规范中硬编码可能失真的数值。
- 失败不得只用 Toast/Banner；错误与对应附件相邻，并通过读屏 live region 播报一次。
- “取消上传”必须真实终止上传与临时处理，不得只是隐藏进度。
- App 进入后台或连接重建时保留未发送草稿；若系统撤销临时文件访问，应明确标记该项需重新选择，不能无限 Spinner。

#### 5.4.5 附件辅助功能

- 附件按钮标签为“添加附件”；截图动作标签为“截取当前 Harness 工作台”；移除按钮标签包含对象，如“移除附件，季度报告 PDF”。
- 每个预览项作为一个语义组，依次读出类型、名称、大小、上传状态和可用动作；装饰性缩略图不重复朗读。
- 选择完成后播报“已添加 {count} 个附件”；失败只播报一次原因；上传进度按有意义的阶段或至少 10% 变化播报，禁止逐字节刷屏。
- 读屏和 Switch Control/开关控制用户可完成：打开附件菜单、选择来源、在系统选择器选取、预览、移除、取消上传、重试与发送。
- 最大辅助字号下，附件预览名称、状态与移除动作都可达；横向预览区必须有可感知的滚动行为，不能把操作藏在仅视觉可见的滑动手势中。

## 6. 连接、错误与空状态

### 6.1 统一状态模型

| 状态 | 界面表现 | 主操作 | 次操作/规则 |
| --- | --- | --- | --- |
| 未配对 | 配对首页 | 扫描二维码 | 改用配对地址 |
| 验证中 | 配对页内进度，禁用重复提交 | 无 | 可取消并返回编辑 |
| 首次连接中 | 无工作台内容时显示居中状态 | 无 | 连接超过 10 秒显示“连接设置” |
| 已连接 | 工作台；状态默认不占空间 | 无 | 连接设置中显示“已连接” |
| 网络断开 | 保留工作台快照，顶部状态条 | 无，自动恢复 | “连接设置” |
| 自动重连 | 保留上下文，单一进度指示 | 无 | 不显示倒计时，不连续弹 Toast |
| 电脑不可达 | 内联错误卡 | 立即重试 | 连接设置 |
| 配对失效 | 阻断错误页 | 重新配对 | 可先查看诊断 |
| 工作台加载慢 | 工作台占位/顶部条 | 立即重试 | 继续自动等待 |
| 无会话 | 工作台内容区空状态 | 新建会话 | 打开会话列表 |
| 搜索无结果 | 搜索区内空状态 | 清除筛选 | 不误导为网络错误 |

### 6.2 状态呈现原则

- Spinner 只表示当前确有进行中的操作；不可用无限 Spinner 表示未知失败。
- 自动重试时说明“会自动重试”，不要要求用户重复点击。
- 相同错误连续发生时只更新同一个状态容器，不堆叠 Toast、Alert 或系统通知。
- 错误卡固定包含：短标题、用户能理解的原因、一个主恢复动作、必要时一个次动作。
- 破坏性动作只使用系统确认对话框；取消在 iOS 左侧/默认位置，破坏性动作标红且使用准确对象名。
- “忘记这台电脑”确认文案：
  - 标题：**“忘记这台电脑？”**
  - 正文：**“此设备上的配对信息和 Harness 登录数据将被移除。下次连接需要重新扫描二维码。”**
  - 操作：**“取消”** / **“忘记电脑”**（破坏性）

### 6.3 Android 手机控制状态

手机控制页按完成度组织，而非假设线性三步：

1. 顶部总状态：**未设置 / 可开启 / 已开启**。
2. “无障碍服务”卡：状态、用途、去系统设置动作。
3. “状态通知”卡：状态、用途、按需请求；Android 13 以下显示系统无需额外授权，不保留不可点击按钮。
4. “屏幕捕获与文件”说明卡：强调按次系统授权，不预先申请。
5. 总开关：**“允许这台已配对电脑操作手机”**。
6. 常驻破坏性动作：**“立即停止手机控制”**，关闭总开关、清空待执行命令、停止捕获。
7. 安全边界说明，保持密码、支付、银行、验证码、账户安全、清除数据、静默安装/卸载和权限绕过始终拒绝。

敏感操作确认必须明确动作、范围和“一次性”：按钮使用 **“允许本次”** 与 **“拒绝”**。焦点初始落在标题，读屏依次读出动作、风险边界和按钮；默认焦点不得落在允许按钮。

## 7. 视觉 token

所有平台使用语义 token，不在页面中散落十六进制颜色。iOS 映射到系统动态色和文本样式；Android 映射到 day/night 资源及系统字体缩放。

### 7.1 颜色

| Token | 浅色语义 | 深色语义 | 用途 |
| --- | --- | --- | --- |
| `color.background` | system/background | system/background | 页面底色 |
| `color.surface` | secondary system background | secondary system background | 卡片、工具栏、输入区域 |
| `color.surfaceElevated` | tertiary/elevated | tertiary/elevated | Sheet、菜单、浮层 |
| `color.textPrimary` | label/high emphasis | label/high emphasis | 主标题、正文 |
| `color.textSecondary` | secondary label | secondary label | 辅助说明 |
| `color.separator` | separator | separator | 分隔线、边框 |
| `color.accent` | 品牌蓝，须满足对比度 | 提亮后的品牌蓝 | 主操作、选中态 |
| `color.success` | 系统绿 | 系统绿 | 已连接、已开启 |
| `color.warning` | 系统橙 | 系统橙 | 加载慢、权限不完整 |
| `color.danger` | 系统红 | 系统红 | 错误、破坏性操作 |

要求：

- 正文与背景对比度至少 4.5:1；大文本和粗图形至少 3:1。
- 连接、警告、错误必须同时有文字或图标，不只靠绿/橙/红。
- 品牌色不可用于大段正文。
- 禁用态仍需可读，不能仅靠降低至极低透明度。

### 7.2 字体

使用系统字体和语义样式，不指定固定字族：

| 用途 | iOS | Android 参考 | 约束 |
| --- | --- | --- | --- |
| 页面大标题 | `.largeTitle` / `.title` | 28–32sp | 最多两行，不锁高 |
| 区块标题 | `.headline` | 17–20sp medium | 随字号缩放 |
| 正文 | `.body` | 16sp | 行高约 1.35–1.5 |
| 辅助正文 | `.subheadline` | 14sp | 关键信息不得低于此级别 |
| 注释 | `.footnote` | 12–13sp | 仅用于非关键补充 |
| 按钮 | `.body.weight(.semibold)` | 15–16sp medium | 允许换行，动词优先 |

不得将文字转为图片；HARNESS 品牌徽标以外的英文大写不得用于正文或操作。

### 7.3 间距、圆角与层级

- 基础网格：4；常用间距为 8、12、16、20、24、32。
- 页面水平边距：iPhone/手机 20；紧凑屏最小 16；iPad 内容区建议最大宽度 640。
- 卡片内边距 16；卡片间距 12；表单字段间距 16。
- 圆角：输入/普通按钮 10–12；卡片 14–16；大 sheet 20–24。系统组件优先系统默认。
- 阴影只表达真实层级；深色模式优先描边和表面亮度差，不依赖黑色阴影。
- 分隔线使用 1 px 视觉厚度，不使用装饰性大面积边框。

## 8. 导航与触控

- iOS 返回使用系统 chevron 和边缘返回手势；不得在按钮文本中手工加入“‹”。
- Android 使用系统返回预测行为；扫码页返回必须取消扫码，工作台返回先关闭顶层 UI，再显示连接设置或退出确认。
- 主要按钮默认充满表单内容宽度；并列按钮只用于短且同层级的选择。
- 触控目标最低 iOS 44×44 pt、Android 48×48 dp；图标可小，但可点击区域不可小。
- 长按、滑动、悬停不得成为唯一入口；所有隐藏手势都有可见按钮等价项。
- 主操作可在成功扫描、成功连接、立即停止时使用轻量触觉反馈；错误不连续震动。
- 尊重“减少动态效果”：禁用大幅位移、视差和持续脉冲；状态切换用淡入淡出或系统默认转场，建议 150–250 ms。
- 加载进度不伪造百分比；Web 已提供真实进度时才显示 determinate 进度。

## 9. 动态字体与布局适配

### 9.1 必须支持的范围

- iOS：从 Extra Small 到最大 Accessibility Size。
- Android：系统字体缩放至少验证 0.85×、1.0×、1.3×、2.0×。
- 显示缩放、分屏、横屏、刘海/挖孔和底部手势区域均不得遮挡操作。

### 9.2 实施规则

- 文本容器使用内容驱动高度；除纯图标触控区域外，不给含文本按钮固定高度。
- 大辅助字号下，水平按钮组改为垂直；标题和工具按钮分行；表格转为卡片或允许有明确标签的横向滚动。
- 状态说明允许完整换行，不用省略号截断错误原因和安全边界。
- 配对页在小屏/大字号下可滚动，主按钮不因底部说明被挤出页面。
- 键盘、输入法候选栏和系统权限页返回后，焦点与滚动位置保持稳定。
- WebView 不禁用页面缩放来掩盖布局问题；正文应响应系统文字大小。

## 10. VoiceOver 与 TalkBack

### 10.1 语义和顺序

- 每页只有一个清晰页面标题；进入页面、sheet 或错误页时焦点先到标题。
- 装饰性品牌图 `accessibilityHidden` / `contentDescription=null`；有意义图标必须有本地化标签。
- 图标按钮标签描述动作，如“连接设置”“关闭扫码”，不描述图形如“回转箭头”。
- 卡片内容按“标题—状态—说明—操作”合并或分组，避免逐字碎片化导航。
- 开关必须同时暴露名称、开/关值和禁用原因；不要把整个卡片和内部开关都设为可点击造成重复焦点。
- Web 与原生焦点顺序必须连续；打开或关闭原生层后焦点返回触发控件。

### 10.2 动态播报

只播报关键转折，避免高频网络状态刷屏：

- “正在连接电脑”首次出现时播报一次。
- 路线内部切换不逐条播报；超过约 5 秒仍未连接时播报一次“仍在连接，会自动重试”。
- 成功播报“已连接到电脑”。
- 网络断开播报“网络已断开，恢复后会自动重连”。
- 需要用户行动的失败立即播报标题和主操作。
- Android Toast 不得作为唯一反馈；重要结果同步更新可聚焦状态区域。iOS 临时 Banner 同理。

### 10.3 扫码与工作台

- 扫码页读屏顺序：关闭、标题/说明、取景状态、改用配对地址（若显示）。相机画面本身不获取焦点。
- 会话消息按消息块导航，暴露发送者、时间（如有）和正文；代码块提供“复制代码”独立动作。
- 流式生成内容不逐 token 播报；完成一个语义段落或生成结束后再通知。
- 自定义 Web 控件必须有正确 role、name、state、value；仅有 `title` 不视为合格标签。
- 在 VoiceOver/TalkBack 开启时完整验证系统返回、抽屉、设置 sheet、菜单、编辑器和确认对话框。

## 11. 深色模式与外观

- 默认跟随系统；如工作台支持外观选择，提供“跟随系统 / 浅色 / 深色”，默认“跟随系统”。
- 原生壳与 Web 工作台必须同步外观，切换时不闪白、不重载或丢失草稿。
- 状态栏、导航栏、启动页和相机页图标明暗必须与当前背景匹配。
- 深色模式禁止直接沿用浅色 `#FFFFFF` 卡片、`#F7F8FA` 背景、`#17313B` 文字等固定值。
- 图片、二维码取景框、代码高亮、选中态、错误卡和禁用态需单独验证对比度。
- 纯黑只用于相机取景等沉浸场景；普通工作台优先系统深色表面，避免强烈黑白跳变。

## 12. 文案规范

### 12.1 术语表

| 概念 | 统一文案 | 避免 |
| --- | --- | --- |
| 桌面端设备 | 电脑 | Desktop（正文中）、桌面、主机混用 |
| 产品 | DeepSeek Harness | deepseek HARNESS 的多种拼写 |
| Web 内容区 | Harness 工作台 / 工作台 | 桌面工作台、网页端混用 |
| 配对凭据 | 配对信息 | 登录码、密钥（非技术诊断场景） |
| 删除配对 | 忘记这台电脑 | 断开、重新配对（动作不准确） |
| 网络恢复动作 | 立即重试 / 自动重连 | 刷新、重启线路 |
| Android 控制能力 | 手机控制 | 接管手机、远程操控 |
| Android 总开关 | 允许这台已配对电脑操作手机 | 允许当前会话（对象不稳定） |

### 12.2 写作规则

- 先说用户结果，再说技术细节；一条状态只表达一个主要事实。
- 按钮使用“动词 + 对象”：扫描二维码、打开系统设置、忘记电脑、立即停止手机控制。
- 不用感叹号制造紧迫感；错误不责备用户。
- “安全”“加密”必须有可验证范围，例如“端到端加密的远程线路”，避免“绝对安全”。
- 省略号 `…` 只表示操作正在进行，不用于普通按钮或静态标题。
- 动态错误先映射为用户语言；原始异常只出现在诊断详情。
- 所有文案进入本地化资源；中文不保留多余句尾空格，变量用本地化占位符。

### 12.3 推荐关键文案

- 配对标题：**连接到 Harness Desktop**
- 配对说明：**在电脑上打开“手机同步”，然后扫描一次性二维码。**
- 主操作：**扫描二维码**
- 后备操作：**改用配对地址**
- 连接中：**正在连接电脑…**
- 自动恢复：**网络已断开，恢复后会自动重连。**
- 加载慢：**已连接电脑，工作台仍在加载。**
- 配对失效：**配对已失效。请在电脑上重新生成二维码。**
- iOS 能力说明：**iPhone 和 iPad 只能访问 Harness 工作台，不能控制其他 App。**
- Android 停止结果：**手机控制已停止，待执行操作已清空。**

## 13. 分阶段实施顺序

### 阶段 A：可恢复与可访问（发布阻断）

1. 补齐相机拒绝恢复页、配对失效与连接失败状态。
2. 为连接动态状态建立 VoiceOver/TalkBack 播报与焦点策略。
3. 移除含文本控件固定高度，支持最大辅助字号和 2.0× Android 字体。
4. Android 用户文案资源化，补齐关键控件语义标签。
5. Android 建立真正的 day/night 语义色与系统栏同步。
6. 补齐文本、照片、系统文件与当前工作台截图发送；使用系统按次选择器、发送前预览、真实取消与失败/超限恢复。
7. 以 VoiceOver/TalkBack 验证附件闭环，确保所有关键操作达到 iOS 44 pt / Android 48 dp。

### 阶段 B：结构一致

1. 统一两端信息架构和“连接设置”入口。
2. 将 iOS/Android 工作台对齐到共享移动语义槽位与响应式契约。
3. 重构 Android 手机控制页为状态驱动卡片，保留立即停止和安全边界。
4. 统一术语、本地化键和错误映射。

### 阶段 C：平板与精修

1. 实现平板分栏、旋转状态保持和硬件键盘焦点。
2. 对齐减少动态效果、增强对比度与触觉反馈。
3. 建立截图回归矩阵和无障碍自动/人工检查。

## 14. 模拟器与真机真实操控验收

静态源码检查、单元测试和截图快照不能替代真实操控。本节要求测试者在可运行的 iOS Simulator / Android Emulator 上通过可见 UI 实际点击、输入、滚动、选择和取消，并至少在一台对应真机上复核权限、相机、文件访问与辅助功能差异。

### 14.1 测试环境与证据

- 记录应用构建版本、系统版本、设备/模拟器型号、屏幕尺寸、外观、文字大小、读屏开关和网络条件。
- iOS 至少覆盖一台紧凑 iPhone 模拟器与一台 iPad 模拟器；Android 至少覆盖一台紧凑手机 Emulator 与一台大屏/横屏配置。
- 为系统照片库/媒体库准备：普通照片、刚截取的截图、透明 PNG、方向信息不同的照片；为系统文件准备：受支持文件、超限文件、不支持类型和长文件名。
- 测试数据必须为无敏感信息的专用样例；不得使用测试者真实相册、账号文件、验证码或私人截图。
- 每条关键用例保存结果证据：通过/失败、关键步骤截图或录屏、实际播报摘要和缺陷编号。证据不得包含配对密钥、完整本地路径或聊天敏感内容。

### 14.2 iOS Simulator 真实操控

按以下顺序执行，不得仅调用测试接口绕过 UI：

1. 启动未配对 App，实际点击“扫描二维码”，分别验证允许、拒绝后的恢复路径；模拟器无法提供真实相机画面时，必须通过“改用配对地址”继续，而不是将扫码误判为通过。
2. 点击并聚焦聊天输入框，用软件键盘输入中英文、换行与 emoji；再用系统粘贴操作粘贴普通文本，确认草稿、发送和焦点行为。
3. 点击“添加附件”→“照片”，在系统 Photos Picker 中选择普通照片和刚导入/刚截取的截图；取消一次选择器并确认草稿未丢失。
4. 点击“添加附件”→“文件”，在系统 Document Picker 中选择正常文件、长文件名文件，再验证取消、读取失败或失效授权的恢复表现。
5. 点击“截取当前工作台”，确认只捕获当前 App 可见工作台、先预览、可移除，且未点击发送前没有上传。
6. 在预览区逐项打开、关闭、移除并重新选择；发送“文本 + 多附件”，观察准备、上传、成功和部分失败状态。
7. 使用超限与不支持类型样例确认在上传前拦截、显示实际限制，并保留其他有效草稿。
8. 分别在最大辅助字号、深色模式、VoiceOver 与 iPad 横竖屏下重复附件菜单、系统选择、预览、移除、取消和发送关键路径。

Simulator 通过不代表以下真机项通过：真实相机扫码、相册受限访问差异、内存压力下大文件处理、真实网络切换、触觉反馈和系统分享/文件提供器兼容性。

### 14.3 Android Emulator 真实操控

1. 启动未配对 App，实际点击扫码和系统返回；Emulator 无有效相机输入时从可见后备入口改用配对地址。
2. 在聊天输入区实际输入与粘贴文本，验证输入法、系统返回收键盘、草稿保持和发送。
3. 点击“添加附件”→“照片”，只通过系统 Photo Picker 选择普通照片与刚加入媒体库的截图；验证取消不丢草稿，且 App 未请求整个媒体库权限。
4. 点击“添加附件”→“文件”，只通过 Storage Access Framework 选择文件；验证长文件名、取消、临时授权失效和重新选择。
5. 点击“截取当前工作台”，核对可见范围、预览、移除和发送前零上传；不得借助 Android 手机控制的屏幕捕获授权代替聊天截图入口。
6. 以正常、离线、上传中断、不支持类型和超限样例验证预检、取消、重试与部分失败，不允许只观察 Toast。
7. 在 2.0× 字体、深色模式、TalkBack、横屏和大屏配置下重复完整路径；用系统返回依次关闭选择器/预览/键盘，不意外退出工作台。
8. 同时确认 Android“手机控制”的文件按次授权与聊天附件选择是两个独立目的，文案和权限不得混用。

### 14.4 真机复核与通过门槛

- iPhone/iPad 与 Android 真机均需实际完成一次：输入文本、粘贴文本、照片、刚截取的截图、系统文件、当前工作台截图及“文本 + 附件”发送。
- 在系统设置中确认 App 未获得不必要的整个照片库/所有文件访问权限；仅用户明确选择的数据可被预览和发送。
- 使用网络切换与前后台切换验证未发送草稿、附件、取消状态和临时授权处理。
- 使用 VoiceOver/TalkBack 完成一次无视觉协助的附件闭环；所有关键操作达到 iOS 44 pt / Android 48 dp，焦点无陷阱。
- 任一必需输入来源不可发现、未经预览即上传、取消仍继续上传、后台读取相册/存储、重要失败仅 Toast、超限到服务端才发现，均判定为发布阻断。
- 模拟器、Emulator 与两端真机结果全部有证据且无发布阻断缺陷，方可将附件与文本发送标记为验收通过。

## 15. 发布验收清单

### 15.1 信息架构与导航

- [ ] 无配对启动进入配对页；有有效配对启动直接恢复工作台。

## 16. 设计完成定义

一项移动端体验改动只有在以下条件全部满足时才算完成：

1. 同时给出正常、加载、空、错误、权限拒绝和恢复状态。
2. iOS 与 Android 共用任务模型，但分别遵循各自系统导航、权限和返回行为。
3. 支持最大文字、深色、读屏、减少动态效果和安全区。
4. 文案已资源化且符合术语表；错误信息不泄露内部实现。
5. 模拟器/Emulator 通过可见 UI 完成真实操控，并在真机完成配对、网络切换、前后台、忘记电脑、文本与附件发送及平台特有能力复核。
6. 照片、文件和截图仅由用户主动、按次选择或捕获，不后台读取相册或整个存储空间。
7. 不削弱既有加密、存储、权限确认和平台能力边界。
