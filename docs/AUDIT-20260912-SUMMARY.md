## 新增源码修复

### 服务商与模型请求隔离

报告：`AUDIT-20260912-PROVIDERS.md`。

1. 模型目录探测的草稿地址/协议改变后，不再携带原服务商已存密钥与自定义认证头。只有匹配的规范端点（含路径、端口、HTTP/HTTPS）与 API 协议才能复用该路由凭据。
2. 显式填写本次 key 的探测不继承旧自定义头；允许匿名/显式新 key 探测，避免把正常修改地址操作一律禁掉。
3. 目录重定向不能绕开目的地址绑定；prepared 请求校验模型标识；目录 transport 异常不保留可能包含密钥的原始 cause。
4. 安装器保留合法 v3 输入 hash，固定新的 v4 输出 hash，不放宽未知来源拒绝规则。

新增15项加原有29项，共44项，修复成员及独立验证均通过。安装胶合4/4独立通过（真实v3输入迁移，0跳过，临时fixture），总审已接受此项交付。不宣称writeFile安装过程具有中断原子性。

主要代码：`scripts/provider-auth-isolation-patch.mjs`、`scripts/patch-official-runtime.mjs`。

### MCP 保存、并发与恢复

报告：`AUDIT-20260912-UX.md`。

1. 文件持久化成功后才发布新内存配置和处理连接，保存失败不产生幽灵行、提前增 revision 或误停连接。
2. 同一事件轮重复点击只提交一次；保存中保护草稿；写成功与列表读取失败分别反馈，刷新只重试 GET。
3. 持久化成功后 dispose 拒绝，返回“配置已提交 + 连接清理状态未知”，保留句柄，不假称停止、不自动重复启动；客户端明确告警。
4. reconnect 与更新/删除进入同一串行队列，防旧请求跨配置版本重启。

新增14项加既有35项，共49项，修复成员及独立验证均通过（0失败/跳过），总审已接受此项交付；确切命令见验证报告。

主要代码：`plugins/dsh-desktop-mcp-manager/lib/index.js`、`plugins/dsh-desktop-mcp-manager/lib/client.js`。

### 团队自动化：候选未提交，不能算完成

成员复现安全授权仍有效时，过期 revision/hash 或缺少 CAS 字段触发整体撤权；已编写限定于安全校验之后的可恢复 CAS 拒绝候选及正反测试。另对 ready 成员等待入场后的陈旧状态重新读取，避免 Stop 期间仍投递。

**该成员异常退出，未完成 claim 绑定提交，也未交付最终报告。候选不可作为已验收成果，更不能直接用于发布。** 独立10文件检查在runtime创建/派生/转达流程挂起后终止，保留部分输出。进一步发现强代码级等待环证据：新增ready relay（index.js:9196–9209）在`store.read`回调内返回异步`queueAgentTeamPrompt`；真实read（4311–4321）持有全库`queueStoreMutation`并await reader。测试的relayGate未释放时，另一startTeam变更被读锁挡住，而释放gate又要等该变更，形成等待环。新增autopilot fake store未实现真实串行锁而漏检。对应旧基线大测试曾完成；精确60秒有界诊断最终回执见验证报告，不能把候选未结束输出算通过。

后续恢复原生产任务时，应在真实store上复现并修复锁内等待外部dispatch，同时保留最新授权、Stop和pauseEpoch校验，不能简单移除安全检查。该候选当前保留以供审查；不覆盖或回退此前他人脏修改。维护源码与安装运行时功能版本不同，不能声称已修复安装版的全部等待/入场错误。

## 当前自动续行阻碍

本轮运行时实测：

1. `team_message` 对running/ready成员报 `team worker admission timed out before activation`，留下 `failed_delivery`；普通父子消息可送达，但不能以此绕过失败成员恢复授权。
2. 目标查询为 `activation: disarmed`，团队状态没有可验证的 active autopilot grant。
3. 安全计划重提交被拒绝：`automatic plan recommit requires the exact admitted Goal round`。新增交互测试契约任务因此取消，未启动成员、未改这些测试。
4. 用户在问答卡选择“继续原范围审计”后，`update_goal resume` 仍被运行时拒绝为“requires a direct human turn on a top-level agent”；团队成员恢复同样拒绝。

这不是用户未同意。是问答确认未被当前运行时识别为恢复所需的新直接聊天轮次。本轮不伪造授权、不修改运行实例或通过普通消息绕过失败恢复。需下一条直接聊天消息才能继续尝试正式恢复、补齐团队交付与其余审计。
