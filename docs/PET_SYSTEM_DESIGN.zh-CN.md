# 女仆鲸 TOK 宠物系统设计方案

状态：Harness Desktop 1.0.9 已实现
适用项目：Harness Desktop
设计目标：在不修改官方 DeepSeek Harness 核心界面的前提下，为桌面版增加本地宠物、任务状态提示和 TOK 养成体验。

## 1. 产品定位

女仆鲸不是新的聊天界面，也不参与模型回答。它是桌面壳提供的可选陪伴功能，用三件事增强桌面版辨识度：

1. 用动画显示当前任务状态。
2. 把模型实际产生的 token 转换为虚拟食物 TOK。
3. 在任务成功后播放原创庆祝舞蹈。

功能必须满足以下边界：

- 不读取、移动、吞掉或删除用户文件。
- 不读取提示词、回复正文、API 密钥和文件名。
- 宠物发生故障时不能阻断工作台启动、会话或更新。
- 默认没有永久死亡；饥饿归零后进入休眠，可随时恢复。
- 不使用梁文锋的姓名、肖像、声音或网络视频素材。
- 女仆鲸素材单独遵循 CC BY-NC-SA 4.0，不并入软件的 MIT 授权。

## 2. 用户能看到的形态

### 2.1 顶部入口

在桌面壳顶部右侧增加一个与现有按钮一致的小鲸鱼图标，位于窗口控制按钮左侧。

- 单击：只打开“女仆鲸”小面板，不打开整个设置页。
- 图标状态：睡眠、工作中、等待用户、完成、异常。
- 小红点仅表示“任务需要处理”或“有完成结果”，不用作营销提醒。
- 首次升级不弹引导页，宠物默认收起；用户第一次点击“唤醒”后才显示桌面浮窗。

### 2.2 宠物小面板

面板只保留高频功能：

- 唤醒 / 收起女仆鲸
- 当前状态和正在关注的任务
- 饱食度
- TOK 仓库：精炼 TOK、标准 TOK、TOK 碎片
- 立即喂食
- 自动喂食开关（默认开启）
- 桌面置顶开关
- 动画强度：完整 / 精简 / 静止
- 打开宠物设置

### 2.3 桌面浮窗

女仆鲸使用桌面壳自己的透明独立窗口，不注入官方网页布局。

- 可拖动，记住每台显示器上的位置。
- 默认置顶，但可以关闭置顶。
- 不显示任务栏图标。
- 支持右键“收起”“喂食”“返回当前任务”。
- 点击宠物返回 Harness Desktop；若有多个任务，打开简洁活动列表。
- 透明区域不阻挡鼠标，角色可见区域可以交互。
- 全屏应用、演示模式或系统锁屏时自动暂停动画。

## 3. 状态系统

宠物只有一个主要任务状态，饥饿、心情是叠加状态，不与任务状态抢占。

| 状态 | 触发条件 | 动画 |
| --- | --- | --- |
| 休息 | 没有任务运行 | 坐下、眨眼、轻摆尾巴 |
| 工作中 | 任一任务正在生成或调用工具 | 整理文件、敲键盘、搬运 TOK |
| 等待用户 | 任务需要批准、回答或选择 | 举提示牌、轻敲窗口 |
| 任务受阻 | 任务失败或遇到系统错误 | 冒问号、短暂失落 |
| 已完成 | 任务成功且用户尚未查看 | 挥手、显示完成标记 |
| 庆祝 | 新任务成功完成 | 6 至 8 秒原创舞蹈 |
| 饥饿 | 饱食度低于 25 | 动作变慢、看向 TOK 仓库 |
| 休眠 | 饱食度为 0 或用户收起 | 睡眠静态画面，不做永久死亡 |

多任务优先级固定为：

`等待用户 > 任务受阻 > 已完成/庆祝 > 工作中 > 休息`

这与官方 OpenAI Pets 的任务状态优先思路一致，但 TOK、饥饿和庆祝舞蹈属于本项目自己的功能。

## 4. TOK 经济规则

### 4.1 计数来源

只使用 DSH runtime 已产生的结构化使用量，不从页面文字或 DOM 中抓取。

- 主要计数：`outputTokens`
- 不计入食物：`inputTokens`、`cacheReadTokens`、`cacheWriteTokens`
- `reasoningTokens` 是否已包含在 `outputTokens` 中，需要在实现前用两个真实模型样本确认；未确认前不能重复计数。
- 服务商不返回 usage 时，可用回复字符数做本地估算，但必须在统计中标记为“估算”。
- 同一个 turn/step 只结算一次，重连或刷新不能重复产粮。

### 4.2 产量

首版建议使用容易理解且不鼓励刷长回复的规则：

`基础 TOK 数量 = ceil(有效输出 token / 512)`

- 每次至少 1 个，单个任务最多 12 个。
- 子代理产量汇总到父任务，共享 12 个上限。
- 取消任务最多结算 1 个 TOK 碎片。
- 失败任务不发完成奖励。
- 成功完成任务额外获得 2 个 TOK，其中至少 1 个为标准或精炼等级。

### 4.3 质量

不在界面上把模型称为“好模型”或“差模型”。显示名称为：

- 精炼 TOK：高营养
- 标准 TOK：普通营养
- TOK 碎片：低营养，可合成

质量由“模型能力基线 + 实际任务结果”共同决定，避免仅按品牌硬编码：

| 信号 | 质量影响 |
| --- | --- |
| 模型元数据明确标记为旗舰/高能力 | 小幅提高 |
| 未知或自定义模型 | 使用标准基线，不歧视 |
| 任务成功完成 | 大幅提高 |
| 多次重试、取消或报错 | 降低 |
| 完成了工具操作且最终成功 | 提高 |

实现时使用 0 至 100 的内部质量分：

- 70 及以上：精炼 TOK
- 40 至 69：标准 TOK
- 低于 40：TOK 碎片

模型基线最多影响 20 分，任务结果至少影响 40 分。这样强模型更容易产出高质量 TOK，但便宜模型完成好任务时同样能获得好食物。

### 4.4 饱食度

- 饱食度范围：0 至 100。
- 仅在应用开启且用户处于活动状态时消耗；关闭应用、锁屏和睡眠期间完全暂停。
- 每 15 分钟活动时间消耗 1 点。
- TOK 碎片恢复 4 点，标准 TOK 恢复 10 点，精炼 TOK 恢复 18 点。
- 自动喂食在饱食度低于 60 时触发，优先消耗刚好够用的低等级食物。
- 仓库上限 999；达到上限后不再累积，但任务功能不受影响。
- 0 饱食度只进入休眠。任意一个 TOK 即可唤醒。

## 5. 舞蹈与动画资产

### 5.1 动画清单

MVP 至少包含：

1. idle：待机
2. working：工作
3. needs-input：等待用户
4. blocked：受阻
5. ready：完成
6. hungry：饥饿
7. sleeping：休眠
8. feeding：吃 TOK
9. celebrate：原创庆祝舞蹈

庆祝舞蹈只借用“任务完成后跳舞”的概念，不临摹网络视频人物、镜头或连续动作。

### 5.2 资源格式

建议使用无代码的宠物包：

```text
maid-whale/
  pet.json
  preview.webp
  idle.webp
  working.webp
  needs-input.webp
  blocked.webp
  ready.webp
  hungry.webp
  sleeping.webp
  feeding.webp
  celebrate.webp
  LICENSE.txt
  ATTRIBUTION.md
```

- 动画资源使用透明 WebP 或固定帧精灵表。
- 首版目标 30 FPS 以下，普通状态建议 12 至 18 FPS。
- reduced-motion 模式只显示每个状态的代表帧。
- 宠物包只允许 JSON、图片和许可证文本，禁止 JavaScript、HTML 和可执行文件。
- 所有相对路径必须经过目录穿越、文件大小、图片尺寸和解压炸弹检查。

### 5.3 授权

现有 `maid-atelier` 素材链已记录为：上善 → zipzip → Small-tailqwq，许可证为 CC BY-NC-SA 4.0。

- 新增的宠物动作属于改编素材，也应按 CC BY-NC-SA 4.0 单独发布。
- `THIRD_PARTY_NOTICES.md`、宠物面板“来源”页和宠物包内都保留署名、来源、修改说明和许可证链接。
- 安装包、发布页和 README 不得把女仆鲸素材描述为 MIT。
- 项目继续保持非商业发布；未来商业化前必须更换素材或取得单独授权。

## 6. 技术架构

### 6.1 分层

```text
官方 DSH runtime
  -> Pet Event Adapter（只读取结构化任务事件和 usage）
  -> Pet Domain Service（状态优先级、去重、TOK 结算、饥饿）
  -> Pet State Store（用户目录中的本地状态）
  -> Pet BrowserWindow（透明宠物窗口）
  -> Shell Pet Panel（顶部入口与设置）
```

### 6.2 更新隔离

- 不修改官方 Harness 源码和 React 组件。
- 不依赖官方页面的 class 名、按钮文字或 DOM 结构。
- Pet Event Adapter 是唯一允许感知 DSH 事件格式的模块。
- 官方升级导致协议变化时，只更新适配器，不动宠物窗口、TOK 规则和用户数据。
- 宠物偏好和仓库保存在 Electron `userData` 中，安装升级不能覆盖。
- 宠物资产首次运行时按版本复制到 `userData/pets/maid-whale/`；升级新资产使用新版本目录，失败可回退旧版本。

### 6.3 建议模块

```text
electron/pet/pet-event-adapter.cjs
electron/pet/pet-domain-service.cjs
electron/pet/pet-state-store.cjs
electron/pet/pet-window.cjs
electron/pet/pet-pack-service.cjs
electron/pet/pet-preload.cjs
renderer/pet/index.html
renderer/pet/pet.js
renderer/pet/pet.css
renderer/pet-panel.js
renderer/pets/maid-whale/*
```

### 6.4 IPC 边界

只暴露明确的方法：

- `pet:getState`
- `pet:setAwake`
- `pet:setPreferences`
- `pet:feed`
- `pet:move`
- `pet:openActivity`
- `pet:onStateChanged`

渲染层不能直接读写文件、启动进程或访问任意 URL。

## 7. 本地数据设计

现有 `app-state.json` 只保存轻量偏好。宠物数据拆成两部分：

### `app-state.json` schema v4

```json
{
  "pet": {
    "enabled": true,
    "awake": false,
    "alwaysOnTop": true,
    "autoFeed": true,
    "motion": "system",
    "muted": true,
    "positionByDisplay": {}
  }
}
```

### `pet-state.json`

```json
{
  "schemaVersion": 1,
  "fullness": 80,
  "inventory": { "refined": 0, "standard": 0, "fragments": 0 },
  "lifetime": { "tasksCompleted": 0, "tokensObserved": 0, "tokProduced": 0 },
  "lastUsageCursor": {},
  "lastActiveAt": null
}
```

- 原子写入并保留一个备份。
- `lastUsageCursor` 用于防止程序重启后重复结算。
- 不保存提示词、回复正文、项目路径、文件名、密钥和完整会话日志。
- 日志仅记录事件类型、时间、匿名 session id 哈希和结算数量，默认保留 7 天。

## 8. 性能与稳定性预算

- 宠物窗口空闲 CPU 目标低于 1%。
- 空闲动画 12 FPS；工作和舞蹈最高 24 FPS。
- 窗口隐藏后停止渲染计时器。
- 单个宠物包解压后目标小于 20 MiB。
- 主窗口关闭时先保存状态，再关闭宠物窗口。
- 宠物初始化超时或资源损坏时自动收起，并写入可诊断日志；不能影响主窗口。
- 禁止轮询官方页面。事件适配器没有新事件时不工作。

## 9. 实施阶段

### 阶段 A：技术探针

- 用两个真实服务商确认 DSH usage 事件字段和 reasoning token 关系。
- 确认任务开始、等待批准、成功、失败、取消的稳定事件。
- 确认多任务和子代理的 parent/child 关联字段。
- 输出一份事件样本，不记录内容正文。

通过条件：能在不读取 DOM 的前提下稳定识别状态，并准确去重 token。

### 阶段 B：静态宠物 MVP

- 新建透明宠物窗口。
- 实现唤醒、收起、拖动、多显示器位置恢复和 reduced motion。
- 使用 PixiJS 高分辨率分层骨骼模型验证 Shimeji 式状态机、桌面行走、拖拽、抛掷、跌落和着地；头部、身体、手臂、腿、后发、裙摆和尾巴独立绑定，不再让整张立绘随窗口平移。

通过条件：连续启动、升级、显示器切换后位置正常，主工作台无卡顿。

### 阶段 C：TOK 与状态联动

- 接入事件适配器。
- 实现产粮、去重、仓库、饱食度、自动喂食和多任务优先级。
- 加入顶部宠物面板。

通过条件：正常、失败、取消、重连、子代理五类场景结算正确。

### 阶段 D：正式动画与授权交付

- 制作九组女仆鲸动画和原创庆祝舞蹈。
- 补齐改编说明、署名和 CC BY-NC-SA 4.0 源文件。
- 完成动画性能和透明区域点击测试。

通过条件：素材来源可追溯，静止模式完整，普通电脑无明显掉帧。

### 阶段 E：打包与发布

- 增加 schema v4 迁移测试、宠物包安全测试和打包自测。
- 安装版、便携版分别验证升级保留状态。
- 先本地运行确认，再发布稳定版。

## 10. 验收清单

- [ ] 宠物入口不打开整个设置页。
- [ ] 官方页面升级后，宠物主体和历史 TOK 不丢失。
- [ ] 不产生 token 时绝不凭空增加 TOK。
- [ ] 同一 usage 事件刷新、重连、重启后不重复结算。
- [ ] 无 usage 的服务商能降级估算且明确标记。
- [ ] 子代理 TOK 不突破父任务上限。
- [ ] 等待用户状态优先于其他任务。
- [ ] 饥饿为 0 不会永久死亡，不影响工作台。
- [ ] 锁屏、休眠和关闭应用时不扣饱食度。
- [ ] reduced-motion 下无持续动画。
- [ ] 宠物浮窗不会阻断窗口控制按钮和主要输入区。
- [ ] 宠物模块损坏时主应用仍能启动。
- [ ] 用户数据中不出现提示词、回复、文件名或 API 密钥。
- [ ] 安装包和仓库保留完整署名及非商业说明。

## 11. 本期明确不做

- 永久死亡、惩罚性复活和付费复活。
- 读取或吞食真实文件。
- 联网排行榜、账号同步、宠物 NFT 或付费抽卡。
- 让模型额外评价自身回答质量。
- 使用梁文锋或其他真人的肖像、声音和视频动作。
- 允许宠物包执行脚本。
- 把宠物逻辑直接写进官方 Harness UI。

## 12. 冻结建议

建议首个可发布版本冻结为：

- 一只女仆鲸
- 九种状态动画
- 三种 TOK 品质
- 自动喂食
- 桌面浮窗与顶部小面板
- 多任务状态提示
- 原创完成舞蹈
- 纯本地数据

成长等级、换装、更多宠物、手动质量配置和云同步留到实际用户反馈后再决定，避免首版再次形成大而难验收的子系统。
