## 权限与生命周期边界

- **运行时端口**：PR 使用 49152–65535 安全动态端口、回环独占探测和有限重试。静态契约继续约束随机范围、异常传播、关闭探测以及耗尽失败，不通过 Chromium unsafe-port 白名单或忽略证书错误绕过安全策略。探测关闭至子进程绑定存在操作系统竞争窗口，仍须依赖启动失败处理，不能将其他进程认作当前运行时。
- **会话持久化**：本次修正旧端口 0 测试断言为安全端口分配与启动身份契约；保留 `assertLocalRuntimeSender` 对实际 runtime origin 的检查，以及 sessionMenu sync/setFlag、独立窗口 preload、ID 数量上限与禁止越权接口断言。没有改产品的持久化实现或授权策略。
- **团队加载**：PR 中首次 SSE 握手有界等待、停滞连接释放属于连接可用性处理，不新增 Goal、成员唤醒或 Stop 绕过权限；本次补正未改变该实现。
- **手机网络**：WSS 旧连接 close/error 回调按连接代次隔离；清单 HTTP/WS 内部鉴权上下文一致，取消贯穿准备和请求，teardown 吸收关闭错误并有界收敛。不得公开内部鉴权头或将异常原文作为公开诊断。
- **手机控制与界面**：命令与回执绑定精确设备连接身份，陈旧结果拒绝；连接提示、失败重试和附件可访问性变化不新增权限、不绕过确认，不自动重发用户消息。

## 云端协作缓存时序补正

负责人返回云 run `34031410376` 的门禁结果：同一提交 Windows/Linux/iOS 通过，macOS 普通测试在 `project-business-sync-api.test.cjs` 的协作缓存等待超过约 10 秒。该结果证明当次等待耗尽，不足以确认产品协议竞态或现场网络根因。

源码区分两个阶段：`recordInboundReceiptAndCompleteOutbox` 持久化命令终态；safeCache 只由后续 capability/event.pull/event.page 路径更新。测试夹具将刷新设为 60 秒，runtime 重试上限为 30 秒，但原等待只有 10 秒，且反复 recoverBoth/5ms/allSettled 会增加 hello 与存储竞争并吞掉恢复错误。生产 API 已通过 business runtime 的 `refetch` 通知驱动重新读取。

本次不改产品代码，仅将两个等待改为订阅同一 refetch 信号后立即检查、防丢通知、串行合并检查；每阶段显式发起一次恢复并传播错误，不在状态检查循环里反复强制恢复。保留真实 HTTP 成功、接受回执、hasAssignee 和所有拒绝/撤销/隐私断言，另要求缓存版本不落后于已接受回执。统一 120 秒有限截止时间覆盖 60 秒刷新、30 秒最大退避及 30 秒 runner I/O 余量；成功/失败/超时都释放订阅和计时器，无新增 sleep、无无限等待、无平台跳过。未将旧 fixture 初始化或撤销流程扩展为新任务。

这是一项基于现有协议状态通知的测试确定性修正，不是证明所有产品竞态不存在。成员未运行附加测试或手工重跑 workflow；新提交仍须由同一发布器重新绑定并通过云门禁。
